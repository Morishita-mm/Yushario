## Orca 内蔵ブラウザでの追加確認

- 使い捨ての AGENT_CHARACTER_HOME と `--no-open` を使って built bin を起動し、この worktree の Orca 内蔵ブラウザだけで確認した（外部ブラウザは起動しない）。
- 起動中に「スマホ」が現れ、登録を押すと QR（324×324 canvas）、コピー可能な pairing string と残り秒数が出た。
- 実 Node crypto の test phone が窓口へ pair を送り、Mac に端末名・6桁 SAS・承認／やめるが出た。Mac の承認後に phone は HTTP 200／registered:true を復号でき、端末一覧に表示された。
- 確認中に既存 `.actions` の CSS が hidden を上書きする1点を発見し、`#mobile-dialog [hidden]` に修正した。再 build 後、非表示操作の computed display が `none` であることを再確認した。
- カメラによる読み取りや実 OS の生体認証を行ったとは主張しない。検証用 listener／端末／ブラウザ tab／データは片付けた。

## 変更・追加依存・エミュレーター向け手順

変更ファイルの範囲：

- `src/server/mobile/`：crypto、store、HTTP、pairing、operations、push、画面 API、既存状態／報告の表示値と、その real HTTP／共有ベクトル検査。
- `src/server/relay.ts`、`relay-hooks.ts`、`permissions.ts`：別 listener への直接接続、スマホだけでも120秒の既存許可を待つこと、監査の配送前保存。既存の認可を弱めない。
- `src/server/quest-db.ts`、`quest-ledger.ts`：既存台帳の最近50件の報告を読む。schema の変更なし。
- `src/core/startup.ts` と test、`scripts/dev.mjs`、`scripts/yushario.mjs`：明示 flag／help と dev 引数の転送。
- `src/web/rpg/app.html`、`main.ts`、`mobile.ts`、`mobile-api.ts`、`mobile.css`、`package.json`／lock、`NOTICE`：既存の見た目の登録 UI と QR。
- `docs/MOBILE.md`、`ARCHITECTURE.md`、`PLATFORM.md`、`docs/security/`：実装の境界・起動手順・検証と未実施項目。

追加依存は **qrcode-generator 2.0.4 だけ**。QR の独自実装を避けるための小さな実行時依存なしの符号化器で、暗号には使わない。ライセンスは NOTICE に追加した。`MOBILE-PROTOCOL.md` と共有 JSON の wire 仕様には **変更なし**。

```sh
npm run dev -- --mobile 127.0.0.1:8791 --no-open
# または:
npm run build
node scripts/yushario.mjs --mobile 127.0.0.1:8791 --no-open
```

Mac 画面の「スマホ」で、アプリに渡す接続先を **`http://10.0.2.2:8791`** に直してから登録する。Android エミュレーターから Mac の127.0.0.1へ届くため、待受は127.0.0.1のままでよい。QR または文字列を別アプリへ渡し、SAS を両画面で比較し Mac で承認する。flag なしでは listener を作らず入口も隠れる。
