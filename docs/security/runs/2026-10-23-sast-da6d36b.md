source は上表の `server/`・`web/` に `src/` を付けたもの。CodeQL 抑制コメントや path 除外は追加していない。既存非 mobile の checks/static の競合は一覧に残し、脅威境界を同一 OS の敵対コードまで広げるなら FD／symlink 境界の再設計が必要で、今回は大規模変更を行わない。

CQ04 は悪意ある同一 OS 利用者を仮定しなくても、**偶発的な同時起動**で nonce の単一所有者を破るため AR とせず修正した。旧処理の順序は A/B がともに dead PID を読む → A が旧 lock を消し新 lock を作る → B がその新 lock を消し、自分の lock を作る、となりうる。

`da6d36b` は coordinator の明示承認に従い、`openSync("wx")` だけで取得し既存 lock を自動削除しない。新 lock は PID／開始時刻の JSON、旧 PID 形式も診断で読める。起動拒否は短い日英の1行で、正確な絶対パスを shell quote した `rm --` と「同じ HOME の全 Yushario の停止確認」「state.json を残す」を出す。異常終了後は [MOBILE の復旧手順](../../MOBILE.md#窓口の再起動とロックの復旧)で lock だけを意図的に消す。

SEC-05 に実 FS／実 HTTP の3ケースを追加し、stale legacy lock の連続拒否、state の byte 保存、lock だけを消した後の元の登録・連番での暗号通信、構造化／不正 lock の安全な診断、引用符を含むパスを確認した。不正 lock の生の内容はログに出さない。
