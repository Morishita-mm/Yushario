## 実装した観測点

- Expo send ticket の data は object／要素1個の配列の両方を検査。provider の生の message は破棄し、error code は許可リストだけ。
- ticket ok の後、**5秒 → 追加30秒 → 追加120秒**で getReceipts を最大3回照会する。HTTP は各10秒上限。見つからない／照会失敗は最終的に未確認で止め、通知本体を再送しない。
- ticket／receipt の DeviceNotRegistered では、送信時と同じ token がまだ登録されている場合だけ消す。更新済み token を遅い receipt で消さない。
- `time/deviceId/kind/ticketStatus/receiptStatus/errorCode` の6項目だけを記録。time は試行開始時刻。token、ticket ID、provider message、題・本文・許可 ID・コマンドは保存しない。
- メモリ履歴50件、0600の `mobile/push-delivery.jsonl` と1世代の `push-delivery.previous.jsonl`、各32KiB・合計64KiB以下。破損した末尾と超過ファイルも有界に読み直す。
- token なしは明示的な NoPushToken。同時処理も50件に制限し、超過は QueueFull。終了／再起動の未完了分は GatewayStopped／Interrupted の未確認。古い試行の遅い receipt が最新結果を上書きしない。
- Mac のスマホ画面に端末別の最後の結果を出し、認可済み `POST /api/mobile/test-push`（deviceId だけ）と「テスト通知を送る」を追加。固定文言・kind=permission で、その1台だけへ送る。許可要求や判断を新規作成しない。
- receipt ok の表示は「配送済み（FCM/APNs 受理）」で、端末表示・音・閲覧の保証でないと明示。旧サーバーの画面を開いている場合は再起動案内を出し、未対応のボタンを無効にする。
