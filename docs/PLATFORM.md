# 開発プラットフォームとしての仕様（勇者の指揮）

町やフィールドで様子を見るだけでなく、ここからエージェント（勇者）を出し、指示し、報告を受け、終わらせる。
絵と画面の作りは `docs/ART.md`、状態の読み取りは `docs/OBSERVATION.md`。

以下は段階ごとの設計判断と変更の記録。古い段階の制限は後の決定で置き換わる。現在の境界は `docs/ARCHITECTURE.md`、起動・操作の案内は README を参照する。

## 前提

- **特定の IDE に依存しない。** 勇者はこのアプリの **埋め込みターミナル**（node-pty）で起動する。1ターミナルにつき現在の Claude Code / pi セッションが1勇者（段階5）。CLI 内でセッションを切り替えたら旧勇者は退場する。
- 起動時にアプリが Claude のフック設定（`--settings`）／pi の拡張を付ける。利用者が `~/.claude/settings.json` を編集する必要はない。
- 起動時にターミナルの ID を環境変数で渡し、フックがイベントに添える。勇者とターミナルの対応が確実にわかる。
- ブラウザを閉じても勇者（PTY）はサーバー側で動き続け、開き直すと再接続して直前の出力も見られる。
- 外のターミナルで起動した Claude Code も、フックを入れていれば町に現れる（「外から来た勇者」の印）。待機中への指示・中断・/compact・みおくるはできず、見ることと作業中の指示だけ。

## プロジェクト＝町

- 作業ディレクトリの git リポジトリを1つのプロジェクトとし、リポジトリ名の町にする。ワークツリーは同じ町の別の勇者。
- 町のすがた（草原の村・海辺の港町・雪国の町・砂漠のオアシス・火山の町）は、初めて町に入る時に選ぶ。選んだ地方に町ができ、あとから変えられる。
- ワールドマップ：動いている町だけを出す（勇者がいない町は「ねむっている町」の一覧へ）。1つの地方の町が 5 つ以上なら「港町 ×6」の1つの印にまとめ、クリックで一覧。
- **でんれい**：全プロジェクト横断で、許可待ち → 呼び出し → 新しい町 → 苦戦中 → 未読の報告 の順に並べる。クリックでその町・勇者へ。

## 報告

- 材料：作業を終えた時のフックの `last_assistant_message`（最後の返答の本文）と、そのターンの集計（使ったツール、触ったファイル、テストの成否、失敗、かかった時間、MP の増減）。
- 本文はローカルの表示だけに使う。外部へ送らない（Jev 連携は廃止）。保存しない（「ぼうけんの きろく」はサーバーのメモリ上のみ）。
- 描写：編集を含む作業＝勝利して宝箱、調査（読む・探す・Web だけ）＝巻物を持ち帰る、単純な応答（ツールなし）＝話しかけてくる（吹き出し）。
- 未読の間は「！」付きで揺れる。確認しても印は残る（あとから読み返し・返事をするため）。消えるのは勇者を「みおくる」時。
- 「へんじ」にはその場で返事を書ける。待機中の勇者に新しい依頼として届く。
- 報告ウィンドウの「ターミナルで ひらく」は、その勇者の埋め込みターミナルを開く。
- ウィンドウの外のクリック・Esc・「とじる」で閉じる。

## 勇者のコマンド（クリックで開く）

町・フィールドの勇者をクリックすると、勇者のそばにコマンドウィンドウが開く。

| コマンド | 中身 | 届け方 | 使える時 |
|---|---|---|---|
| **たたかいを みる** | その勇者の戦闘にフォーカス | 画面の切り替え | フィールドで戦闘中 |
| **めいれい** | 自由文の指示 | 作業中：次のツールが終わった時にフックから差し込む（`PostToolUse` の `additionalContext`）／待機中：ターミナルに新しい依頼として送る | いつでも |
| **さくせん** | 定型の指示（いったん止まって報告して／テストを通して／コミットして／方針を見直して） | めいれいと同じ | いつでも |
| **にげる** | 中断（Esc を送る） | ターミナル | 作業中だけ |
| **やすむ** | 会話の整理（`/compact`） | ターミナル | 待機中だけ |
| **ターミナル** | その勇者の埋め込みターミナルを開く | 画面 | いつでも |
| **きろく** | 報告と最近の行動 | 画面 | いつでも |
| **みおくる** | セッションを終える（下記） | ターミナル（`/exit` 相当） | いつでも（作業中は確認） |

- 作業中のめいれいは、届くまでの状態（「つたえる まち」→「つたえた」）を出す。1回の作業で何度も割り込むとエージェントが混乱し MP も減るので、目安を出す。
- ターミナルで打っている最中に画面から送ると文字が混ざるので、待機中の送信は確認を挟む。
- やらないこと：許可の自動承認、画面からの任意コマンド実行、既存の勇者を別プロジェクトへ移すこと（新しい勇者を出す）、長い会話の画面（ターミナルで行う）。

## みおくる・よびもどす（セッションの終わり）

- **みおくる**：勇者が町の門まで歩き、手を振って旅立つ。Claude Code を正しく終了させる。作業中なら「中断して旅立たせますか？」と確認する。
- 旅立った勇者は **ぼうけんしゃの めいぼ** に残る：名前、プロジェクト、旅立った時刻、最後の報告。報告と、こちらから送った返事も読み返せる。
- **よびもどす**：めいぼから選ぶと、同じセッションを再開して（`claude --resume <セッションID>`）門から町に戻ってくる。
- 勧め：報告をすべて確認済みで、しばらく待機している勇者には「そろそろ旅立ちますか？」の印を出す（決めるのは利用者）。
- めいぼが長くなったら、古いものから奥へしまう（再開できる期間には限りがありうる）。
- 「解雇」「死亡」のような言葉は使わない。

## しゅつじんの土台（実装仕様・段階1）

ここまでの構想のうち、**勇者を埋め込みターミナルで出し、ブラウザを閉じても動き続け、どの勇者がどのターミナルか分かる** ところまでを作る。
町・フィールドの描画、報告、コマンドは次の段階（この段階では作らない）。

### サーバー：セッション（勇者のターミナル）

- `src/server/pty.ts` を、**サーバーが持ち続ける複数のセッション** に作り替える。1セッション＝1つの PTY。
  - セッションは `{ id, preset, cwd, project, createdAt, exited?: { code } }` と、出力の直近 **256KB** を保持する。
  - `id` はランダムな短い文字列。上限は **16 セッション**（超えたら作成を拒否）。
  - ブラウザの切断ではセッションを終わらせない。終わるのは「終了」の操作、プロセスの終了、サーバーの停止の時だけ。
  - プロセスが終わったセッションは一覧に「終了」として残し、明示的に消すまで出力を読める。
- 子プロセスの環境変数：今の `AGENT_CHARACTER_URL` に加えて **`AGENT_CHARACTER_SESSION=<id>`**。
  サーバーのトークンを渡さない処理は今のまま（`TYPESAFE_API_KEY` の扱いは Jev 廃止で不要）。
- 作業ディレクトリ（`cwd`）：**絶対パスで、存在するディレクトリ** だけを受け付ける。省略時は今と同じ既定（`AGENT_CHARACTER_CWD` → `INIT_CWD` → `process.cwd()`）。
- `project`：`cwd` から上へたどって git のリポジトリ名を求める（ワークツリーは本体のリポジトリ名）。git でなければフォルダ名。
- プリセットは今と同じ 4 つ（shell / claude / pi / codex）だけ。任意のコマンドは受け付けない。claude のフック設定（`--settings`）は今のまま。

### API（すべてトークン必須・自分のオリジンのみ。今の WS の条件と同じ）

| 操作 | 方法 |
|---|---|
| 一覧 | `GET /api/sessions` → `[{ id, preset, cwd, project, createdAt, exited }]` |
| 作成 | `POST /api/sessions` `{ preset, cwd? }` → 作成したセッション |
| 終了 | `DELETE /api/sessions/:id` → プロセスを終了し、一覧からも消す |
| 接続 | `WS /pty?session=<id>&cols&rows` → まず保持している出力を送り、その後は今と同じ入出力（`{type:"input"}` / `{type:"resize"}`）。同じセッションに複数の画面がつないでもよい |

トークンは今の WS と同じく `?token=` で受け取る（API も同じ）。

### フック・イベント

- `adapters/claude-code/hook.mjs`：環境変数 `AGENT_CHARACTER_SESSION` があればイベントの `terminal` に、`cwd` から求めたリポジトリ名を `project` に入れる（どちらも最大 200 文字）。
- `src/core/events.ts`：`terminal` と `project` を受け付ける（短い文字列）。ローカル表示だけで使う（`deciderEvent`・Jev は廃止）。
- `src/core/room.ts`：`RoomAgent` に `terminal?` と `project?` を持たせる（最新のイベントの値）。

### 画面（最小限）

- 埋め込みターミナル（当時は `/live2d.html`、段階5で廃止。現在は `/terminal.html`）を新しい API に合わせる：作業ディレクトリの入力欄、「起動」で作成して接続、セッションの一覧から選んで接続、「終了」。
- 接続中のセッション ID を `sessionStorage` に覚え、ページを開き直したら同じセッションに再接続する（直前の出力が表示される）。
- 町の画面（`/`）や RPG の見た目への組み込みはしない（次の段階）。

### やらないこと（この段階）

- セッションの永続化（サーバーを再起動したらセッションは消える）、`--resume` での再開、ワークツリーの作成
- 町・フィールド・報告・コマンドの画面
- 新しい抽象化（ファクトリ、イベントバス、汎用ストアなど）や、要求にない設定項目

## 町の画面を本物にする（実装仕様・段階2）

`/mock.html` で決めた画面の構成（ワールドマップ・町・宿屋・3つのフィールド・戦闘フォーカス）を、メイン画面 `/` で **実際のエージェント（Room）** で動かす。
報告・でんれい・コマンドは次の段階（この段階では作らない）。

### 描画の部品を「データを受け取る形」にする

- 今の `src/web/art/mock-*.ts` は描画とモック用の偽データが一体になっている。描画関数は **表示するデータを引数で受け取る** ように直し、偽データは `/mock.html` 側に残す。
- `/` と `/mock.html` は同じ描画関数を使う（描画コードを複製しない）。`/mock.html` の見た目と操作は今のまま保つ。
- 置き場所は `src/web/town/`（描画）とし、`src/web/art/` には gallery と mock の入口と偽データを残す。ファイル名の `mock-` は描画側から外す。

### Room から画面へのつなぎ（`src/core` の純粋関数・テスト付き）

- **プロジェクト**：`agent.project`（無ければ `agent.name`）ごとにまとめる。
- **表示名**：同じプロジェクトで同じ名前の勇者は、町に来た順に `main-2`・`main-2 (2)`・`main-2 (3)` とする。ID が変わらない限り番号は変わらない。
- **居場所**（勇者ごとに1つ）：
  - 戦闘：`battleMonster(activity)` があるとき。スライム＝そうげん、ゴーレム＝どうくつ、おばけ＝よるのもり、ドラゴン（任せた仕事）＝そうげん。
  - 宿屋：居眠り（`dozing`）のとき。
  - 町：それ以外（待機・考え中・読む・調べる 等）。
- **パーティー**：`agent.helpers`（サブエージェント）の職業は `jobOf`。

### 画面

- **ワールドマップ**：勇者が1人以上いるプロジェクトを町として出す（印・人数・戦闘中の数）。同じ地方で 5 つ以上ならまとめて一覧（モックと同じ）。サーバー起動後に見たが今は誰もいないプロジェクトは「ねむっている町」。
- **町のすがた**：初めて入る時に5種類から選ぶ（モックの選択画面）。選んだものはブラウザの `localStorage` に保存する（プロジェクト名ごと）。
- **町**：町にいる勇者が通りを歩く。宿屋をクリックで中、門から各フィールドへ（モックと同じ）。
- **フィールド**：その町の勇者の戦闘だけを出す。モンスター・対象（ファイル名やコマンド）・パーティー。戦闘の置き場所が足りない時は、入りきらない人数を「ほか N人」と出す。
- **戦闘フォーカス**：フィールドで勇者をクリックすると、その勇者の戦闘にフォーカスする（モックと同じ。クリックで戻る）。
- **右のステータス窓・許可の吹き出し・メッセージ欄（時刻付き）** は今の `/` の仕組みをそのまま使う（ステータス窓は選んだ勇者のもの）。
- 勇者が来た・旅立った・戦闘が始まった/終わった時、画面上の勇者は今の居場所へ移る（瞬間移動でよい。歩いて移るのは後で）。
- 場所の移動はモックのタブではなく、地図上の操作（町の門、立て札、ワールドマップへ戻るボタン）で行う。

### 片付け

- 今の `/` の手描きの町（`src/web/rpg/` の scene・world・actors・sprites・effects のうち使わなくなるもの）は削除する。`/live2d.html` はこの段階では触らない（段階5で廃止）。

### やらないこと（この段階）

- でんれい・報告・コマンドメニュー・みおくる/よびもどす（段階3・4）
- 町のすがたのサーバー保存、勇者が歩いて場所を移るアニメーション、新しい絵の生成
- pi など Claude Code 以外の勇者を出すこと

## 町の台帳と設定（実装仕様・段階2.5）

動かしたことのある町（プロジェクト）を、サーバーを再起動しても忘れないようにする。長く使われていない町は自動でしまう。

### 台帳に載る町

- **このアプリから起動した勇者**（埋め込みターミナルのセッション）のプロジェクトだけを台帳に載せる。過去の履歴（`~/.claude/projects` 等）からは取り込まない。
- 外のターミナルから来た勇者（イベントに `terminal` が無い）は、動いている間だけ町に出し、台帳には載せない（終われば消え、ねむっている町にも残らない）。
- 町の記録：`{ name, path, theme?, firstSeenAt, lastActiveAt, pinned, archivedAt? }`
  - `name` はプロジェクト名（段階1の `project`）、`path` は最後に起動した作業ディレクトリ。
  - `lastActiveAt` は、その町のアプリ起動の勇者のイベントが来るたびに更新する。
  - 町のすがたは台帳に保存する（段階2のブラウザ保存をやめ、台帳に移す）。

### 保存

- JSON ファイル：`<データフォルダ>/towns.json` と `<データフォルダ>/settings.json`。
- データフォルダは `AGENT_CHARACTER_HOME`、無ければ `~/.config/agent-character`（無ければ作る）。
- 書き込みは一時ファイルに書いてから置き換える（途中で落ちても壊れない）。読めない・壊れている時は空として起動し、壊れたファイルは `*.broken` に退避する。
- SQLite は使わない（報告などの履歴を保存する段階で改めて判断する）。

### しまう（自動の片付け）

- 設定 `archiveAfterDays`（既定 **30**。`0` は「しまわない」）。
- サーバー起動時と、その後 1 日ごとに判定する：勇者がいない・ピン留めでない・`lastActiveAt` が設定の日数より古い町に `archivedAt` を付ける。
- しまった町はワールドマップとねむっている町の一覧から消え、「しまった町」の一覧にだけ出る。
- しまった町は、一覧から「もどす」か、その町にアプリから勇者が来ると自動で戻る（`archivedAt` を消す）。すがたは覚えている。
- 判定は `src/core` の純粋関数にしてテストする。

### API（トークン必須。段階1の `/api/sessions` と同じ検査）

| 操作 | 方法 |
|---|---|
| 町の一覧 | `GET /api/towns` → 台帳の全件 |
| 町を変更 | `PATCH /api/towns/:name` `{ theme?, pinned?, archived?: false }` |
| 設定 | `GET /api/settings` → `{ archiveAfterDays }`、`PUT /api/settings` `{ archiveAfterDays }`（0〜365 の整数） |

台帳や設定が変わったら、状態 WS（`/ws`）で `{ type: "towns", towns }` を送り、開いている画面を更新する。

### 画面

- ワールドマップ：町＝「台帳のしまっていない町」＋「今いる外から来た勇者のプロジェクト」。勇者がいない台帳の町は「ねむっている町」。
- 「しまった町 N」の札を出し、一覧から「もどす」。
- 町の画面とねむっている町の一覧に「ピンどめ」の切り替え（ピン留めの町はしまわれない）。
- 右上に「せってい」：RPG 風の窓に「町を しまうまで：しまわない / 7日 / 14日 / 30日 / 90日」。選ぶとすぐ保存。

### やらないこと（この段階）

- 過去の履歴の取り込み、町の削除（しまうだけ）、その他の設定項目
- SQLite、報告・名簿の保存（段階3・4）

## しゅつじんとターミナル（実装仕様・段階2.6）

町の画面 `/` だけで「勇者を起動する → 話しかける → 様子を見る → 会話を確認する」ができるようにする。
会話は埋め込みターミナルをそのまま見せる（吹き出しや報告にするのは段階3）。サーバーの API は段階1・2.5 のものを使い、新しい API は作らない。

### しゅつじん（起動）

- 上部に「しゅつじん」ボタン。RPG 風の窓（既存の窓の見た目）で：
  - **勇者の種類**：Claude Code / Codex / pi / shell（段階1 のプリセット。既定は Claude Code）。
  - **行き先（作業ディレクトリ）**：台帳のしまっていない町（`path`）から選ぶ。町の画面にいる時はその町を初期選択。「ほかの フォルダ」で絶対パスを直接入力できる。
  - 「しゅつじん！」で `POST /api/sessions`。成功したら、その勇者の町へ移り（すがたが未選択なら先に選ぶ）、**会話窓（段階3）** を開く。勇者が町に着くまでは「勇者が 町に むかっている…」と出し、その間に送った最初の依頼は勇者の準備ができてから伝わる。ターミナルは会話窓の「ターミナルで みる」から。失敗したら窓の中に理由を出す。
- 同じ窓に「ひらいている ターミナル」の一覧（`GET /api/sessions`）を出し、選ぶとそのターミナル窓を開く（shell など町に現れない勇者のターミナルにも戻れるように）。終了したセッションは「おわった」と出す。

### ターミナル窓（会話）

- 画面の上に大きな窓で埋め込みターミナルを開く（`WS /pty?session=`。保持している出力が先に出るので、それまでの会話が見える）。
- 窓の見出しに勇者の名前（いなければプロジェクト名とプリセット）。「とじる」・Esc・窓の外のクリックで閉じる。**閉じても勇者は動き続ける**（セッションは終わらせない）。
- 開く入口：
  - 右のステータス窓の勇者に「ターミナル」ボタン（イベントに `terminal` がある勇者だけ。外から来た勇者には「外から来た勇者（このアプリの ターミナルでは ない）」と出す）。
  - しゅつじん窓の「ひらいている ターミナル」一覧。
- `src/web/terminal.ts` の「1つのセッションに接続して xterm に表示する」部分を共通にし、`/terminal.html` とこの窓で使う（複製しない）。`/terminal.html` の動きは今のまま。

### やらないこと（この段階）

- 勇者をクリックして出るコマンドメニュー、めいれい・さくせん・にげる・やすむ・みおくる（段階4）
- 報告・会話の吹き出し化（段階3）
- セッションの終了ボタン（終わらせるのは段階4 のみおくる。ターミナルで `/exit` を打てば終わる）

## はなす（実装仕様・段階3）

勇者との会話を、ターミナルではなく RPG の会話窓でできるようにする。町の勇者をクリックすると立ち止まり、コマンド窓が出る。ターミナルは「ターミナルで みる」として残す。

### 会話の中身（フック → サーバー → 画面）

- `adapters/claude-code/hook.mjs`：UserPromptSubmit の `prompt` と、Stop の `last_assistant_message` を、イベントの **`text`**（最大 8000 文字）に入れる。それ以外のフックでは送らない。
  - これまでの「プロンプトや出力の本文は送らない」方針を、この2つに限って変える。**本文はローカルの relay と画面だけで使う**（Jev・`deciderEvent` は廃止）。ファイルには保存しない（サーバーのメモリ上の履歴だけ）。README のプライバシーの説明も合わせる。
- `src/core/events.ts`：`text`（最大 8000 文字の文字列）を受け付ける。ローカル表示だけで使う（`deciderEvent` は廃止）。
- `src/core/room.ts`：`RoomAgent.talk: { at, from: "you" | "hero", text }[]`（直近 30 件）。UserPromptSubmit の `text` は `you`、Stop の `text` は `hero`。画面は replay とライブのイベントから組み立てる（会話専用の保存や API は作らない）。

### 返事を送る（サーバー）

- `POST /api/sessions/:id/say` `{ text }`（1〜8000 文字。トークン等の検査は `/api/sessions` と同じ）→ `200 { delivered: boolean }`。終了したセッションは 409、未知は 404。
- サーバーはセッション（`terminal`）ごとに勇者が待機中かを、そのセッションの最後のイベントで判断する：SessionStart / Stop / StopFailure の後は待機中、UserPromptSubmit・ツールのイベントの後は作業中。まだイベントが無い時は作業中として扱う。
  - **待機中**：その場で PTY に本文を書き、少し（300ms）おいて Enter（`\r`）を送る → `delivered: true`。
  - **作業中**：預かる → `delivered: false`。そのセッションの次の Stop（または SessionStart）で、預かった本文（複数なら改行でつないで1つ）を同じ方法で送る。
- 預かり中の本文が変わったら、状態 WS に `{ type: "pending", terminal, texts }` を送る（接続直後にも、預かりのあるセッションの分を送る）。

### 勇者のコマンド窓（画面）

- 町を歩いている勇者をクリックすると、その場で立ち止まってこちらを向き、そばにコマンド窓（既存のモックの見た目）：**はなす / ようすを みる / ターミナル**。窓を閉じると歩き出す。
- 宿屋のベッドの勇者、フィールドで戦っている勇者からも同じ窓（フィールドでは先頭に **たたかいを みる**）。
- 「ようすを みる」は、その勇者の **つよさ窓**（会話窓と同じ系統の RPG 風 dialog）を開き、右のステータス窓でもその勇者を選ぶ。名前と Lv、数値付き HP/MP、いまの行動と続いている時間、気分のチップ、クエストの一覧と達成数、なかまと職業、さいきんの きろく（新しい順に直近12件、時刻と成功 ○／失敗 ×）を出す。開いている間も Room の更新を反映し、勇者がいなくなったら「たびだちました」と出す。Esc・とじる・窓の外クリックで閉じ、キー入力は町のショートカットに漏れない。
- 「ターミナル」は段階2.6 のターミナル窓（外から来た勇者は使えない理由を出す）。

### ついていく（勇者を追いかける）

- コマンド窓に **ついていく**。選ぶと、画面がその勇者の居場所を自動で追いかける：町・宿屋にいればその町・宿屋、戦闘が始まればその勇者の**戦闘フォーカス**、戦闘が終われば町（眠っていれば宿屋）に戻る。場所の切り替えは今の暗転・白い光の演出を使う。
- 追いかけている間は、マップの上に「▶ 勇者名に ついていく（やめる）」の帯を出す。
- やめる：帯の「やめる」、自分でマップを移動した時（ワールドマップへ・門・立て札・宿屋の出入り・戦闘フォーカスを閉じる）、勇者が旅立った時（メッセージ欄に知らせる）。
- 追いかける勇者はページの中だけで覚える（保存しない）。

### 会話窓（はなす）

- 画面下に RPG の会話窓。`talk` を `あなた「…」` / `勇者名「…」` で並べ、最新の勇者の返事は1文字ずつ表示。長い返事は「▼」でページ送り、コード（``` で囲まれた部分）は等幅。
- 入力欄と「つたえる」で `POST /api/sessions/:id/say`。結果が `delivered: false` なら「たたかいが おわったら つたえる」と出し、預かり中の本文を会話窓に出す。
- 外から来た勇者（`terminal` が無い）は読むだけ。入力欄の代わりに理由を出す。
- 「ターミナルで みる」でターミナル窓へ。Esc・とじる で閉じる。会話窓で打つ文字は町の画面のショートカットに漏れない。

### 台帳の変更

- shell で起動したセッションは台帳に載せない（外から来た勇者と同じ扱い）。

### やらないこと（この段階）

- 作業中の割り込み（めいれい・`additionalContext`）、さくせん・にげる・やすむ・みおくる（段階4）
- 途中の返事やツール出力の本文の表示、会話の保存（ファイル・DB）
- 報告の宝箱・巻物の演出（段階4以降で検討）

## ほうこく（実装仕様・段階3.5）

会話と報告を **1つの窓** にまとめる。報告は「あなたの依頼 → 勇者の作業 → 最後の返事」の1往復で、会話はその並び。上の「報告」の節（材料・描写・未読の印・へんじ）を、この形で本体に入れる。

### 往復の集計（`src/core`・テスト付き）

- 本体の会話（サブエージェントでない）の UserPromptSubmit で往復を始め、Stop（または StopFailure）で閉じる。往復の間の本体のイベントから集計する：
  - `files`：編集したファイル（Edit/Write 系の `target`、重複なし）
  - `tests`：テスト系の実行の成功数・失敗数
  - `failures`：失敗したツールの数
  - `tools`：使ったツールの数（0 なら単純な会話）
  - `startedAt` / `endedAt`、`mp`：始まりと終わりの MP（context から。わからなければ省略）
  - `kind`：ファイル編集あり＝`chest`（宝箱・しょうり）、ツールなし＝`talk`（吹き出し）、それ以外（読む・探す・Web・テスト・コマンド・git など、編集なしで何かした）＝`scroll`（巻物）
- `RoomAgent.talk` の勇者の返事（`from: "hero"`）に `report`（上の集計）を付ける。UserPromptSubmit が無いまま Stop が来た時は、集計の無い返事として扱う。

### 会話と報告の窓（「はなす」の窓を大きくする）

- マップの領域を覆う大きな窓。過去の往復はスクロールで読める。
- あなたの依頼は吹き出し、勇者の返事は **報告の札**：見出し（宝箱/巻物/吹き出しの印・「しょうり！ ファイル N つを なおした」等・時刻・かかった時間）、集計（ファイル名、テスト ○N ×N、しっぱい N、MP の減り）、本文。長い本文は最初の数行と「▼ つづき」で開く。
- 1文字ずつの表示は **最新の返事だけ**（クリック・Enter で省略は今のまま）。過去の返事はすぐ全文。
- 入力欄・預かり表示・ターミナルで みる・外から来た勇者は読むだけ、は段階3のまま。
- 入口：勇者の「はなす」、勇者の「！」、でんれいの報告。報告から開いた時はその往復の札までスクロールする。

### 未読と知らせ

- 返事が届いた時に、その勇者の会話窓を開いていなければ **未読**。窓でその札が表示されたら既読。既読の記録はブラウザ（localStorage、勇者 id と時刻で、最近の 200 件まで）。サーバーには持たない。
- 勇者の頭上：未読があれば揺れる「！」。既読になっても、次の依頼を送るまで小さな報告の印（宝箱/巻物/吹き出し）を残す（あとで読み返し・返事をするため）。クリックで会話窓。フィールド（戦闘中）では出さない（勇者が依頼なしに作業を続けると、前の報告が戦闘の上に残り続けるため。未読は町の 📜 と会話窓で分かる）。
- 町の名前の札とワールドマップの町の札に、未読の数（📜N）。
- **でんれい**（画面の端の一覧。モックの見た目）：全プロジェクト横断で、許可待ち → 呼び出し → 新しい町（すがた未選択）→ 苦戦中 → 未読の報告 の順。クリックでその町・勇者へ（報告は会話窓のその札へ）。

### 保存

- 報告はサーバーのメモリ（イベント履歴）だけ。再起動で消える。ファイル・DB に保存しない。

### やらないこと（この段階）

- 報告の永続化、通知音・OS 通知、報告の削除、みおくる/よびもどす（段階4）

## 勇者のコマンド（実装仕様・段階4）

上の「勇者のコマンド」「みおくる・よびもどす」の節を本体に入れる。**作業中の割り込み（めいれい・`additionalContext`）はやらない**（使ってみて必要になったら検討）。対象はこのアプリから起動した勇者だけ（外から来た勇者は、使えない理由を出して押せない）。

### コマンド窓に足すもの

| コマンド | 中身 | 使える時 |
|---|---|---|
| さくせん | 定型の依頼を選んで送る：「テストを とおして」「コミットして」「ほうしんを みなおして」（「いったん とまって ほうこくして」は作業を止めず紛らわしいため段階5で削除。止めるのは にげる）。送り方は「はなす」と同じ（待機中はすぐ、作業中は預かる） | いつでも |
| にげる | 作業を中断する（Esc を送る）。預かっていた依頼は捨てる（会話窓に「にげた ので あずかった ことばを すてた」） | 作業中だけ |
| やすむ | `/compact` で会話を整理する（MP 回復） | 待機中だけ |
| みおくる | セッションを終える。作業中なら「中断して たびだたせますか？」と確認し、Esc の後に終える | いつでも |

### サーバー

- `POST /api/sessions/:id/action` `{ action: "interrupt" | "compact" | "farewell" }`（検査は `/api/sessions` と同じ）。
  - `interrupt`：PTY に Esc。預かりを空にし（`pending` 通知）、待機中として扱う。
  - `compact`：待機中だけ。`/compact` と Enter を送る（作業中は 409）。
  - `farewell`：作業中なら Esc、少し待って `/exit` と Enter。5 秒で終わらなければ今の終了処理（DELETE と同じ）で終わらせる。終わったセッションは一覧から消す。
  - 文字の送り方は実際の Claude Code で確かめて決める（コマンドとして解釈される送り方にする）。
- **ぼうけんしゃの めいぼ**（`<データフォルダ>/roster.json`、台帳と同じ保存の仕方）：このアプリから起動した Claude Code のセッションが終わった時（みおくる・`/exit`・プロセス終了）に1件足す。`{ sessionId, name, project, cwd, leftAt }`。**会話の本文は保存しない**。最大 50 件（古いものから消す）。
  - Claude の `session_id` は、そのセッションの `terminal` 付きイベントの `agent` から覚える。
- `GET /api/roster` → めいぼ。`POST /api/roster/:sessionId/recall` → 同じ `cwd` で `claude --resume <sessionId>`（フック設定はいつもどおり）の新しいセッションを作り、めいぼから消す。`sessionId` は Claude のセッション ID の形（英数字とハイフン）だけ受け付ける。

### 画面

- コマンド窓に上の4つ（段階3 のカーソル操作のまま）。さくせんは小さな窓で選ぶ。みおくるは確認窓（はい / いいえ）。
- みおくる：勇者が町の門まで歩いて手を振り、旅立つ（モックの演出を使う）。会話窓・つよさ窓・ついていくは閉じる。
- めいぼ：上部に「めいぼ」ボタン。窓に名前・プロジェクト・旅立った時刻の一覧と「よびもどす」。よびもどすと、その町の門から勇者がやってきて、会話窓を開く（しゅつじん と同じ）。
- MP が少ない時のステータスの助言（今は `/compact` を案内）を「やすむ」の案内にする。

### やらないこと（この段階）

- 作業中の割り込み（めいれい）、会話本文の保存、外から来た勇者の操作、Codex・pi の resume

## 使い勝手の改善（実装仕様・段階4.5）

### 会話窓を少し透かす
- 会話と報告の窓の背景を半透明にし、後ろの町と勇者が見えるようにする（札と文字は読みやすさを保つ）。濃さは見た目を確かめて調整する。

### ターミナル → 会話
- ターミナル窓の見出しに「▶ はなす」（このアプリから起動した Claude Code の勇者がいる時だけ）。押すとその勇者の会話窓へ。

### ステータスをコンパクトに
- 右側の上に「ちいさく / くわしく」の切り替え（ブラウザに覚える）。ちいさく：町にいる勇者全員を1行ずつ（名前・Lv・小さな HP/MP・いまの行動）。行をクリックでその勇者を選び、くわしい札を出す（許可待ちは目立たせたまま）。

### 勇者の名前を変える
- つよさ窓に「なまえを かえる」。1〜24 文字。空にすると自動の名前（`main-2 (2)` など）に戻る。
- サーバーに保存（`<データフォルダ>/names.json`、勇者の ID → 名前、台帳と同じ保存の仕方）。`GET /api/names` → `{ [id]: name }`、`PUT /api/names/:id` `{ name }`（空なら削除）。変わったら状態 WS に `{ type: "names", names }`（接続直後にも送る）。
- 画面の表示名は「付けた名前 → 自動の名前」の順。めいぼに載る名前と、よびもどした勇者の名前も付けた名前を使う（ID は同じ）。

## 使用感レビューの反映（実装仕様・段階5）

初見の利用者によるレビュー（49件）を受けた修正。決まっていないもの（町の建物の役割＝W04、さくせん「いったん とまって ほうこくして」の要不要＝W13、スマホ対応・インターネット経由の利用）はこの段階ではやらない。

### 勇者の種類（エージェント）を増やせる形にする
- 起動できるエージェントを **1か所の表**（id・表示名・起動コマンドと引数・町と会話に対応するか・再開・`/compact`・終了の送り方）にまとめる。最初は **Claude Code・Codex・pi** と shell。新しいエージェントは表に1行足し、必要ならアダプタ（フック）を足して対応させる。プラグイン機構や汎用の基盤は作らない（表とアダプタだけ）。
- `GET /api/agents` → 表の公開部分（`{ id, label, hero, resume, compact }`）。しゅつじん窓はこれで選択肢と対応範囲（「町・会話に対応」「ターミナルのみ」）を出す。shell は「ターミナルのみ（勇者は出ない）」。
- **pi をアプリ産の勇者にする**：pi のアダプタが、Claude Code のフックと同じ形のイベント（セッション ID を `agent`、作業ディレクトリ名を `name`、`project`、`terminal`、セッション開始・依頼（本文）・ツールの開始/終了・返事の完了（本文）・終了）を送る。会話窓からの依頼・にげる・やすむ・みおくるが pi でも使える（pi のコマンドで）。再開は pi が対応していれば対応、なければ「再開できない」としてめいぼに載せない。
- **Codex**：アプリから起動した Codex を町に出せるか（フックや通知の設定を起動時に渡せるか）を調べ、できるなら pi と同じく対応、できなければ表で「ターミナルのみ」と明示する。
- このアプリから起動したセッションが終わったら、どのエージェントでも町から勇者を退場させる（終了の知らせが来なくても）。同じ PTY の `/new`・再開・fork で ID が変われば旧勇者だけ退場し、新セッションの依頼済み判定をリセットする。reload は同じ勇者のまま。依頼の無い新セッションはめいぼに載せない。

### 不具合・小さな修正
- 会話窓の書きかけを、勇者ごとにページ内で残す（ターミナルと行き来しても消えない）。
- 許可の「ターミナルで こたえる」は、その勇者のターミナル窓を開く。
- `python -m unittest`・`python3 -m pytest` などもテストとして数える。
- 報告の所要時間から **許可待ちの時間を除く**（許可要求から、その次の本体のイベントまで）。札に「（きょか まち N を のぞく）」。
- 作業が終わった後の Claude の「入力待ち」の通知（アイドル）は呼び出しにしない。勇者は「つぎの いらいを まっている」（でんれいには出さない）。permission_prompt / elicitation_dialog 等、実際に回答が必要な通知だけが waiting_input の呼び出し。auth_success や入力を終えた pi の UI は呼び出さず、作業中・待機中へ戻す。
- 初めてのフォルダの信頼確認：サーバーがターミナルの出力から信頼確認の画面を見つけたら、状態 WS に `{ type: "attention", terminal, reason: "trust" }`。会話窓は「ターミナルで フォルダの しんらいを こたえてください」と、ターミナルを開くボタンをはっきり出す。
- 作業が終わった時の語りは「町で ひとやすみ」（通常の待機では宿屋に入らず、居眠り時は宿屋）。やすむ（`/compact`）の描写と成功時の語りを宿屋にそろえる。整理の失敗・キャンセルも待機へ戻すが、「せいりできなかった」と知らせ、MP 回復成功とは語らない。
- みおくるの語りは付けた名前を使う。確認の最初のカーソルは「いいえ」。
- ワールドマップにいる時は「◀ ワールドマップ」を出さない。
- フォルダのエラーなど、サーバーのエラー文を日本語に。
- 既読の返事は、開き直した時にすぐ全文を出す（1文字ずつは未読の最新の返事だけ）。
- 会話の本文の部分はほぼ不透明に（透かすのは余白）。
- よびもどした勇者の会話窓に「前の 会話と ほうこくは 画面には もどりません（勇者は おぼえています）」。
- 右側の「ちいさく」一覧の行から、その勇者のコマンド窓を開ける。
- しゅつじん窓の「勇者の種類」に、エージェントごとの対応範囲の説明。

## きょうかい（実装仕様・段階5.1）

「やすむ」（`/compact`）の場所を **きょうかい** にする。宿屋（眠る）と同じく、中に入れる建物にする。

- 勇者が「やすむ」（PreCompact〜PostCompact の間）は、居場所が **きょうかいの中**（宿屋ではない）。祭壇の前でひざまずいて祈る姿（2コマの小さな動き）。終わったら町へ戻る。語りは「〇〇は きょうかいで いのりを ささげている」→「MPが かいふくした！」（失敗時は段階5の扱いのまま）。
- 町の画面：きょうかいをクリックで中へ（宿屋と同じ）。中に祈っている勇者がいる間は、町から見たきょうかいの窓が光る。
- きょうかいの中：奥の壁（ステンドグラス）、祭壇、長椅子、じゅうたん。祈っている勇者をクリックでコマンド窓。「▼ そとへ」で町へ。ついていくもきょうかいへ追従する。
- 新しい絵はコンポーネントとして作る（`tools/art/components.json` に追加 → 生成 → `pack.py`）：きょうかいの壁、祭壇・長椅子・じゅうたん・燭台などの小物、祈る勇者（既存の勇者の絵を参照してそろえる）。`/art.html` のコンポーネント一覧に出ること。`/mock.html` にも「きょうかい」の場面を足す。

## リファクタリング：絵の前提をデータへ（段階6）

絵を丸ごと差し替えても（ChatGPT 等で作り直す、利用者が自作の勇者を使う）コードを触らずに済むよう、コードに埋まっている「絵の前提」を絵の情報（manifest）へ移す。**見た目と動きは変えない**（リファクタリング）。利用者のパックを読み込む仕組みと、勇者の見た目選びは、この段階ではやらない。

- **コマは名前で参照する**：`art.draw(ctx, "obj-canal", 1, …)` のような番号ではなく、`components.json` のコマの名前（`"stone bridge"` 等）で引く。
- **足元の位置**：絵ごとの「地面に合わせる点」を manifest に持ち、描く側はそれを使う。
- **絵の中の位置の前提**：橋の水の帯の行・切り出す列など、絵の中身のピクセル位置を前提にした値を manifest の情報にする。
- **色の前提**：勇者の色違いで入れ替える色の段階、背景の水のゆらめきに使う色などを manifest の情報にする（無ければ今の推定のまま）。
- **置き場所**：宿屋のベッド・きょうかいの祈る位置・町の建物などの座標は、絵の大きさ（と足元）から決まるようにするか、絵の情報として持つ。どちらにするかは場所ごとに素直な方を選ぶ。
- **約束事を文書にする**：`docs/ART.md` に「絵の約束事（パックを作る人向け）」の節を作り、ID・コマの名前と並び・大きさ・足元・色の段階などの決まりを書く。manifest がこの約束事を守っているかを確かめるスクリプトを `tools/art/` に置く。
- AGENTS.md に「絵のパック（データのみ）は例外として認める。コードを読み込むプラグインは作らない」と明記する（読み込む仕組み自体は後の段階）。

## そうび：モデルと考える量（実装仕様・段階7）

モデルを **武器**、考える量（effort / thinking）を **アクセサリ** として、勇者に装備させる。新しいモデルが出るたびに武器を増やさずに済むよう、武器の名前は強さの段階で固定し、どのモデルを指すかは **マスタ** で決める。

### マスタ
- リポジトリに既定のマスタ（`src/server/equipment.json`）を置く。`<データフォルダ>/equipment.json` があれば、エージェント単位でそちらを優先する（中身の継ぎ足しはしない）。
- エージェントごとに：
  - `weapons`：`[{ id, name, model }]`。既定は3段階：`dagger`「たんけん」（軽くて速い）、`steel`「はがねの つるぎ」（ふだん使い）、`legend`「でんせつの つるぎ」（いちばん強い）。Claude Code は `haiku` / `sonnet` / `opus`（別名なので新モデルに自動で追従し、利用者の環境に依存しない）。pi・Codex は使えるモデルが利用者のプロバイダ次第なので、**既定のマスタには武器を入れない**（武器の欄を出さない）。使う人が `<データフォルダ>/equipment.json` に自分のモデルを書く。
  - `accessories`：そのエージェントが受け付ける考える量だけ。`[{ id, name, value }]`。名前は「きあいの はちまき」系（例：ふつう / ためる / ためにためる / げんかい）。Claude Code は `--effort` の値、pi は `--thinking` の値。対応しないエージェント（Codex など）は空で、アクセサリ欄を出さない。
- 引数の渡し方（`--model` / `--effort` / `--thinking` / `-m`、途中で変える時のコマンド）は、エージェントの表（`agents.ts`）に持たせる。マスタは名前と値だけ。
- 知らないモデル名はアプリでは検査しない（エージェント自身のエラーがターミナルに出る）。

### 装備しない＝既定
- 武器もアクセサリも **「そうびなし」が既定**。この時は何も渡さず、エージェント自身の設定のモデル・考える量になる。

### サーバー
- `GET /api/equipment` → エージェントごとのマスタ（読み込み済み）。
- `POST /api/sessions` に `weapon` / `accessory`（マスタの id、省略で そうびなし）。起動の引数に足す。
- `POST /api/sessions/:id/equip` `{ weapon?, accessory? }`：このアプリから起動した勇者だけ。待機中はすぐ、作業中は預かって作業が終わった後に、そのエージェントの「途中で変えるコマンド」を送る。途中で変えられないエージェント（表で未対応）は 409。
- 今の装備はセッションに覚え、`/api/sessions` に出す。めいぼにも残し、よびもどす時は同じ装備で起動する。
- 途中の切り替えが実際に効くか（`/model <名前>` がその場で切り替わるか、選択画面が出るだけか、考える量を途中で変えるコマンドがあるか）は、実際の Claude Code と pi で確かめてから送り方を決める。効かないものは「途中では かえられない（しゅつじん・よびもどす時だけ）」とする。

### 画面
- **しゅつじん窓**：勇者の種類の下に「ぶき」「アクセサリ」の選択（既定は そうびなし）。名前の横に本当の値を出す（例：「はがねの つるぎ（sonnet）」）。
- **勇者のコマンド「そうび」**：ぶき・アクセサリを選ぶ小さな窓（さくせんと同じ操作）。作業中は「さぎょうが おわったら もちかえる」。持ちかえたら語り「〇〇は でんせつの つるぎを そうびした！」。
- **つよさ窓**：今の武器・アクセサリ（本当の値つき）。そうびなしは「―（きほん）」。

### やらないこと（この段階）
- 外から来た勇者の装備、マスタを画面から編集すること（武器の見た目と戦闘の演出は段階7.1 でやる）

## そうびの見た目と戦闘の演出（実装仕様・段階7.1）

装備したことが、マップと戦闘で目に見えるようにする。**演出だけ**で、成功・失敗は今までどおり実際の結果で決める（でんせつの つるぎでも失敗は外れる）。そうびなしは今の見た目・数字のまま。

### マップ：剣の色
- 武器の段階で剣の色を変える：たんけん＝鉄色、はがねの つるぎ＝青い鋼、でんせつの つるぎ＝金色（ときどき きらりと光る）。町・宿屋・きょうかい・フィールド・戦闘のどこでも同じ。
- 段階6 の勇者の色違い（manifest の色の段階の入れ替え）と同じ仕組みで、剣の色の段階を manifest に持たせる。新しい絵は作らない。
- 剣の色がほかの部分と共有されていて剣だけ塗り替えられない場合は、代わりに名前札の横に小さな武器のアイコン（コンポーネントとして作る）を出す。
- 色は武器の **段階**（マスタの武器の並び順：1番目・2番目・3番目〜）で決める。マスタを上書きした人でも同じ規則で色が付く。
- アクセサリはマップには出さない。

### 戦闘：ダメージとため
- ぶき：成功した時のダメージの数字の大きさを段階で変える（たんけん＝小さい数字、はがね＝ふつう、でんせつ＝大きい数字で、ときどき「かいしんの いちげき！」）。
- アクセサリ：斬りかかる前の溜めを、考える量の段階（マスタのアクセサリの並び順）で長くし、高い段階では「ちからを ためている…」と出す。
- 数字と溜めの決め方は src/core の純粋関数にしてテストする。

### 段階7 の不具合の修正
- つよさ窓（右の札）に今の装備を出す。
- 待機中に持ちかえてすぐ切り替わった時に「さぎょうが おわったら もちかえる」と出さない（作業中で預かった時だけ）。
- そうび窓の「とじる」の ▶ が二重になるのを直す。

## 調整：レビューの指摘と動画2本（実装仕様・段階8.1）

## 調整：足りない物があっても迷わない（実装仕様・段階8.2）

- 想定外のエラー：1行の説明と、詳しく見る方法（`YUSHARIO_DEBUG=1` でスタックトレース）を出す。

### 画面の中
- 勇者が起動してすぐ（数秒以内に）終わった時：ターミナルの出力を見るよう案内し、装備を付けていたなら「CLI を新しくするか、そうびなしで しゅつじんし直す」も案内する。
- CLI が見つからない時の案内：「入れる → yushario を止めて起動し直す」の順を分かりやすく。

### 確かめ方
- 別のレビュアー（このアプリを知らない人の目）が、npm pack したものを「何かが欠けた環境」で一周する：CLI なし、Claude 未ログイン、古い Node、git なし、書けないデータフォルダ、ポート使用中、ブラウザを開けない、装備を付けた古い CLI 相当。指摘は重大度つき。

## 動画の作り直し：PV の脚本から（実装仕様・段階8.5）

段階8.1 の動画の見せ方を改める。このアプリはエージェントのハーネスやスキルではなく、Claude Code・Codex・pi などの**エージェントをそのまま使うプラットフォーム**。

- **本物のターミナルの表示はデモにも PV にも入れない**（アプリに無い窓に見えるため）。本物であることは小さな注記（本物の作業記録を短縮再生）で足りる。
- **伝えること**：「いろんなエージェントが勇者になって、モンスターと戦う」「退屈なタスクを、冒険に」。キャッチコピーを入れる。
- **PV は脚本から作る**：脚本は案・評価・修正を繰り返して固める。脚本と絵コンテをレビューしてから撮影する。
- 中身は本物の記録だけ（成功・返事・レベルアップを作らない）。複数のエージェントを見せるなら、Codex・pi の本物の記録も撮る（無害な依頼、利用者の設定を書き換えない）。
- デモ動画は PV の後に、同じ方針（本物のターミナル枠なし）で直す。音は動画が完成してから考え直す。
- PV にパーティーの場面を入れる：1人の勇者がサブエージェントを複数（3人程度）同時に使い、仲間と一緒に1体のモンスターと戦う様子（本物の記録）。冒頭の町も、本物の記録で勇者を増やしてにぎやかにしてよい。
- PV v1 は仕様の説明のようで固かった。作り直しは**ゲームの PV（JRPG のトレーラー）の文法**で：説明（「スライム＝ファイル編集」のような対応表）をやめ、物語の口調の短い言葉、勇者の紹介、見せ場の連続、ボス戦の盛り上がり、題字の登場、で「面白い・使ってみたい」と思わせる。特定作品の題字・曲・台詞・演出をそのまま真似ない（構成の型だけ参考にする）。中身は本物の記録のまま。
- PV v2 への利用者の指摘：勇者の紹介が特定のエージェント（Claude Code・pi）に寄りすぎ。「**あなたのエージェントが**」勇者になる見せ方に。今後対応を増やす予定なので、対応エージェントは「ほか順次」程度に少し広く見せてよい（今対応していない物を対応済みとは言わない）。文字は大きく。きょうかいで祈る・宿屋で休む・バイオームごとに町が変わる場面を足し、「意外と作り込んでいる」と思わせる。
- PV の曲と効果音は**魔王魂**（https://maou.audio/）の素材を使う（改変可・商用可・クレジット必須「音楽：魔王魂」）。クレジットは動画の最後と README に。ファイル名に maoudamashii を含める。素材ファイルはリポジトリに入れない（再配布禁止のため）。
- PV v3 への指摘：魔王魂の曲は壮大すぎ。**BGM はコードで作る 8bit 風**に戻し、場面ごと（探索・町、戦闘、休息＝きょうかい・宿屋、パーティーとボス、終わりのジングル）に分けてつなぐ。**効果音は 8bit ではなくフリー素材**（規約を確かめ、クレジットが要る物は書く）。町の見た目の切り替えでは勇者の位置を戻さず、歩きながら町がバイオームごとに変わるように。宝箱を開いて報告を受け取る場面を足す。長さは後で詰める。
- Yushario 版 PV v1 への指摘：町の見た目の切り替えは**勇者の位置を変えず、バイオームだけが変わる**こと（町ごとのカットに分けない）。字幕は句読点を減らし、文言を見直す。サブエージェントの仲間が引きの画面で見えてくる場面は、間に別のカットを挟まずに続ける。ワールドマップには町を複数、町には勇者を複数（本物の記録）置き、勇者の町らしくにぎやかにする。勇者が噴水などの上を歩かないこと（本体のバグなら本体を直す）。
- Yushario 版 PV v2 への指摘：字幕を差し替える（はじめよう／戦いが終わると・報酬が届く／ひとりじゃない → 困難には（ドラゴン）→ みんなで挑め（画面が引いてパーティー）／題字は「退屈な仕事を冒険に」）。下の小さな注記はすべて消す。題字のロゴは左から徐々に現れる。パーティーの仲間は盗賊・戦士・魔法使い・僧侶を1人ずつにする。仲間の見た目はサブエージェントの種類で決まる（Explore＝盗賊、Plan＝僧侶、general-purpose＝戦士、それ以外＝魔法使い）ので、4種類を1人ずつ呼ぶ本物の記録を撮り直す。
- Yushario 版 PV v5 への指摘：最後のキャッチコピー（「退屈な仕事を冒険に」）は、ロゴが出きった直後（44.7 秒）ではなく、曲が一段静かになる所（46.6 秒、終わりの旋律の3つ目のフレーズ titleEase の始まり）で出す。ロゴの出方・曲・ほかのカットは変えない。
- 英語の PV は、アプリの言語を English にして撮る。宝箱の報告に映る勇者の返事も英語にするため、報告の場面の本物の記録を英語の依頼で撮り直し（同じ tiny-quest の3つのバグ修正、依頼の中身は日本語版と同じで「短く英語で報告して」）、英語の PV だけそれを使う。日本語の PV は今の記録のまま。

## 戦闘中のコマンド（実装仕様・段階9）

戦闘のアップ画面から、たたかっている勇者に作戦や追加の指示を出し、にげられるようにする。

### 画面
- 戦闘のアップ画面を自分で開いた時に、右下（下のメッセージ窓の上、重ならない位置）にコマンド窓を出す（「ついていく」で自動で戦闘へ移った時は出さない）。窓を閉じたあとは勇者たちをクリックすると開き直す。コマンド窓と勇者たち以外をクリックすると、今までどおりフィールドへ戻る（案内は「クリックで もどる」）。
- コマンド：**たたかう**（窓を閉じて見守る）／**さくせん**（下の3つから選ぶとすぐ伝える）／**めいれい**（自由に書いて伝える。Ctrl+Enter で送る）／**にげる**（作業を中断＝今までと同じ。作業中だけ）／**もどる**。カーソル操作は町のコマンド窓と同じ。伝えた結果・断られた理由は窓の下の1行に出す。外から来た勇者は さくせん・めいれい・にげる を使えない。
- さくせん（送る文は「さくせん「名前」：内容」）
  - ガンガンいこうぜ：細かい 質問は せずに、自分で 判断して どんどん すすめて
  - いのちだいじに：慎重に すすめて。消す 操作や 大きな 変更の 前には 方針を 聞いて
  - じゅもんせつやく：調べものや 出力は 必要な 分だけに して、会話を 軽く たもって
- 町・会話窓からの依頼は今までどおり（作業中は預かって、終わってから伝える）。
- モックの戦闘画面も同じ窓を出す（伝えた内容はトーストで見せるだけ）。
- モックの勇者のコマンドも本体と同じ窓にする（はなす・ようすを みる・ついていく・そうび・さくせん・にげる・やすむ・ターミナル・みおくる）。モックの勇者は Claude Code か pi のどちらかとして、本体と同じ品ぞろえの偽のそうびを持つ。ようすを みる で そうびを確かめ、そこから持ちかえられる（このページだけ。ぶきを変えると町の剣の色も変わる）。

### サーバー
- `/api/sessions/:id/say` に `steer: true` を足す。作業中でも預からず、すぐ端末へ貼り付けて Enter を送る。Claude Code・pi は作業中の入力を、いまのツールの後で読み、同じ往復のまま続ける（確かめた：返事に指示が反映され、Stop は1回）。待機中なら普通の依頼になる。
- **許可・質問に答える画面が出ている間は断る**（Enter が答えになってしまうため）。許可要求・入力要求の通知・AskUserQuestion で「答え待ち」にし、本筋の次の進み（ツールの終了・次のツール・返事の完了など）か、アプリから許可・拒否した時に解く。遅れて届いた古いフックでは解かない。サブエージェントの許可要求も答え待ちに数える。
- 会話には依頼として残る：Claude Code は作業中の入力でも UserPromptSubmit を出す。pi は拡張の `input`（`streamingBehavior: "steer"`）を UserPromptSubmit として送る。報告は今までどおり最後の依頼からの分を数える。

- 町のコマンド窓・会話窓からの割り込み、Codex への対応、さくせんの編集・追加

## 通知の音（実装仕様・段階10）

作業のためのアプリなので、音は「画面を見ていなくても、手を止めて見るべき出来事」だけに付ける。BGM・戦闘の効果音・歩く音・クリックやカーソルの音・文字送りの音は付けない。

### 鳴らす場面（4つだけ）
| 出来事 | きっかけ | 音 |
| --- | --- | --- |
| 許可を求めている | `permission` が新しく届いた／`attention`（フォルダの信頼確認）が届いた | 高く上がる2音の呼び鈴。4つの中で一番目立つ |
| 報告が届いた | 勇者本人（サブエージェントでない）の `Stop` | やわらかい「ポロン」 |
| 失敗で止まった | 勇者本人の `StopFailure` | 低く下がる2音 |
| レベルアップ | 町の帯に「レベル○に あがった！」を出す時 | 0.6秒ほどの小さなファンファーレ |

- その場で届いた出来事だけで鳴らす。接続し直した時に読み込む過去の出来事、記録の再生では鳴らさない。
- 1つの出来事に1つの音。報告と同時にレベルアップした時は、レベルアップの音だけを鳴らす。
- 同じ音は2秒に1回まで。勇者が何人いても、2秒以内に重なった分は鳴らさない。
- どれも 0.6 秒以内で、音量は控えめに固定する。音量の設定は作らない（OS の音量で調整する）。

### 音の作り方
- 音のファイルは使わない。ブラウザの Web Audio で、その場で8bit風の音（矩形波・三角波と短い音量の山）を合成する。依存パッケージは足さない。
- 音色は試聴ページで利用者が選んだ物（2026-10-13）。notes は［Hz, 開始秒, 長さ秒］。各音は 8ms で gain まで上げ、音の終わりまで直線で 0 に下げる。
  - 許可：`{ wave: "square", gain: 0.064, notes: [[740, 0, 0.08], [988, 0.12, 0.11]] }`
  - 報告：`{ wave: "triangle", gain: 0.042, notes: [[659, 0, 0.1], [784, 0.12, 0.21]] }`
  - 失敗：`{ wave: "square", gain: 0.028, notes: [[262, 0, 0.135], [175, 0.165, 0.175]] }`
  - レベルアップ：`{ wave: "square", gain: 0.027, notes: [[523, 0, 0.075], [659, 0.09, 0.075], [784, 0.18, 0.08], [1047, 0.28, 0.14]] }`

### 音のモード（3つ）
| モード | 鳴る音 |
| --- | --- |
| ぜんいん（最初はこれ） | すべての勇者の4つの音 |
| ついていく勇者だけ | 許可は全員分。報告・失敗・レベルアップは「ついていく」中の勇者の物だけ。誰にもついていっていない時は、許可のほかは鳴らさない |
| なし | 何も鳴らさない |

- 上部の帯の「せってい」の右に、スピーカーのボタンを1つ置く。押すたびに ぜんいん → ついていく勇者だけ → なし → ぜんいん と切り替わる。今のモードは、ドットのスピーカーの絵（ぜんいん：音の波／ついていく勇者だけ：小さな旗などの目印／なし：×）と `aria-label`（「おと：ぜんいん」「おと：ついていく勇者だけ」「おと：なし」）で示す。押した時は町の帯に「おと：○○」と短く出す。
- 選んだモードは町の設定（`archiveAfterDays` と同じ所）に `sound`（`"all"`・`"follow"`・`"off"`）として保存する。前の版の `true` は `"all"`、`false` は `"off"` として読む。保存に失敗した時は表示を元に戻す。
- 「なし」以外に切り替えた時は、報告の音を1回鳴らして確かめられるようにする。
- BGM と戦闘の効果音は付けない。戦闘のアニメは作業中ずっと続くので、1人の勇者に絞っても音が途切れなくなるため。
- ブラウザは、ページを1回操作するまで音を出せない。最初のクリックやキー操作で音を出せる状態にする。それより前の出来事は鳴らさない。そのあとは、別の窓で作業していても鳴る。

## でんれいから飛んだ先の目印（実装仕様・段階10.1）

でんれいのお知らせを押して勇者のいる町・戦場・宿屋・教会へ移った時、同じ所に勇者が何人もいると、どの勇者が呼んでいるのか分からない。移った先で、その勇者に短い目印を出す。

- 勇者の頭の上に、RPG で対象を選ぶ時のような「▼」のドットの矢印を出す。幅30・高さ18ドット、色は帯の金（`#f9c22b`）に2ドット以上の暗い縁取り。上下に 2px ほど、0.5 秒くらいの周期でゆれる。新しい画像は作らず、キャンバスにぼかさず描く。
- 各ポーズの manifest の frame・foot と PNG の透過から求めた絵の上端に、ゆれを含めて2〜6ドットの隙間を空ける。その勇者に報告の札（「！」を含む）が出ている時は、札の上端から2〜6ドット上に置く。ほかの勇者・札・建物名の札より後に描き、画面上端で切れる時だけ画面内まで下げる（勇者に重なっても構わない）。
- 同時に、勇者がその場で2回小さく跳ねる（高さ 4px ほど、1回 0.25 秒くらい）。立ち位置・歩く道・向きは変えない。
- 目印は移った直後から約3秒で消える。その勇者を押した時、別の町・場所・戦闘の画面へ移った時も、すぐに消す。
- 対象は勇者が決まっているお知らせ（許可・呼んでいる・くるしい たたかい・報告）だけ。新しい町のお知らせには出さない。勇者がその場にいない（旅立った等）時は何も出さない。
- 報告のお知らせで会話の窓が開く時も、窓の後ろで目印は出す（窓で隠れても構わない）。
- 「ついていく」で画面が勇者を追う時や、地図で勇者を押した時には出さない（でんれいからの移動だけ）。
- `/mock.html` のでんれいも同じ描画を使う。偽のお知らせ（許可・呼んでいる・くるしい たたかい・報告）に勇者を付け、その勇者のいる町・戦場へ移って目印を出す。

## 画面に収める（実装仕様・段階10.2）

PC やタブレットの大きさでは、メイン画面 `/` をスクロールしなくても、帯・地図・メッセージ・でんれい・つよさがすべて見えるようにする。

- 幅600px以上・高さ500px以上では、ページ全体の高さを画面の高さに合わせ、ページはスクロールしない。
- 幅961px以上（地図と右の列が横に並ぶ時）は、帯・地図の操作・メッセージを先に置き、残った高さに地図を収める。地図は 16:9 のまま、その高さで決まる幅にし、メッセージも同じ幅にそろえる。右の列（でんれい・つよさ）は残りの幅を使う（360〜560px）。右の列が360pxを切る時だけ地図を幅に合わせて縮め、560pxを超える余りは左右に均等に空ける。
- 幅600〜960px（右の列が地図の下に回る時）は、地図は幅いっぱいのまま、でんれいとつよさを残りの高さに入れる。
- でんれいとつよさの列は、入りきらない分だけ列の中でスクロールする。
- 幅600px未満・高さ500px未満（スマホなど）は今のまま、ページをスクロールする。
- 操作で地図の大きさが変わらないこと。地図の上の行（町の操作・ついていくの帯・町の台帳のエラー）は高さ32pxの1行にまとめ、出たり消えたりしても高さを変えない。入りきらない時は文字を「…」で切る。
- 勇者が1人もいない時は、地図の上に別のボタンを出さず、帯の「しゅつじん」を金色にして点滅させる（動きを減らす設定の時は点滅しない）。
- メッセージは4行分の高さで固定し、長い行は折り返さず「…」で切る。
- 地図は町・戦場・ワールドマップ・戦闘のどれでも 16:9 の同じ大きさで表示する。幅で地図が決まる時は、余った高さをメッセージの下に空ける。

## 同じ内容を1か所に（実装仕様・段階10.3）

同じ画面に同じ内容を2回出さない。役目のない表示も出さない。

- 場所の名前は地図の中の題だけに出し、地図の上の行には出さない。題はワールドマップと同じ枠付きの札にし、1行目に町（プロジェクト）の名前を大きく金色で、2行目に場所（「まち（草原の村）」「そうげん」「やどや（なか）」など）を小さく出す。町・戦場・宿屋・教会のどれでも同じ形にする。`/mock.html` も同じ札で、今のモックの町の名前を出す。
- 町の題に未読の報告の数（📜）を出さない。報告は勇者の上の札とでんれいで分かる。
- 戦闘画面の地図の中の「クリックで もどる」は出さない。戻るのはコマンドの「もどる」と地図の外のクリック。
- 帯の接続の表示は、つながっている間は空にし、接続中と切れた時だけ出す。
- 「町のすがたを かえる」は町の中だけに出す。
- ワールドマップの「しまった町」「ねむっている町」は、0 の時は出さず、押せない。
- 町の建物の札は、やどや・きょうかい・としょかん・どうぐや の4つに付ける（どこに何があるか分かるように）。
- 勇者のカードの「ぼうけんの きろく」「さいきんの きろく」は、記録が1件もない時は見出しごと出さない。
- みおくった時のメッセージは「○○を みおくりました。」を先に出し、そのあと勇者の終了で「○○は 旅立っていった。」が続く。門まで歩くといった説明の文は出さない。みおくれなかった時は「○○を みおくれなかった。」と出す。

## 右の列をタブにする（実装仕様・段階10.4）

右の列は「でんれい」と「ゆうしゃ」の2つのタブで切り替える。「ちいさく / くわしく」の切り替えと、勇者を選ぶプルダウンはなくす。

- タブの名前に件数を出す：「でんれい（3）」「ゆうしゃ（8）」。選んだタブはブラウザに覚え、次に開いた時も同じタブにする。
- ワールドマップでは、全町のお知らせ・全町の勇者を出す。町の中（戦場・宿屋・教会も含む）では、その町の分だけを出す。（段階12で変更：許可・呼んでいる・とちゅうで たおれた は、町の中でもほかの町の分を出す）
- **でんれい**：町ごとのまとまりに分け、まとまりの見出しに町の名前と種類ごとの件数を出す（例「audit-town 🔑1 📜2」）。まとまりの順は、いちばん急ぐお知らせを持つ町から。中の並びは今と同じ（許可 → 呼んでいる → 新しい町 → くるしい たたかい → 報告、同じ種類は新しい順）。タブの名前と同じ内容になる「でんれい（n）」の見出しは出さない。
- **ゆうしゃ**：町ごとのまとまりに分け、見出しに町の名前と人数を出す（例「audit-town（3人）」）。中は1人1行の一覧（名前・Lv・HP/MP・していること）。その下に、選んだ勇者のカードと、ほかの勇者の許可のカードを出す。一覧は高さが足りない時だけ一覧の中でスクロールし、カードはいつも見える。
- ゆうしゃのタブも、でんれいと同じ白い枠で囲む。
- でんれいのお知らせを押して勇者のところへ飛んだ時は、ゆうしゃのタブに切り替える（勇者の決まっていない「新しい町」は切り替えない）。
- `/mock.html` も同じタブにする。でんれいは町ごとのまとまりで、町の中ではその町の分だけ。ゆうしゃのタブはアプリと同じ行とカード（同じ部品と見た目）で、モックの町の勇者を偽の hook から作った Room で出す。行を押すとその勇者の場所へ移って目印を出す。
- お知らせの文には町の名前を入れない（見出しと重なるため）。例「hero9から ほうこく」「あたらしい町！ すがたを えらぼう」。

## 英語の画面（実装仕様・段階11）

README と PV には英語版があるのに、アプリの中は日本語だけ。英語でも遊べるようにする。日本語の画面（ひらがな中心の RPG の口調）は今のまま変えない。

### 言語の選び方
- 言語は「日本語」と「English」の2つ。設定（`/api/settings`）に `language: "auto" | "ja" | "en"` を足す。今までの設定ファイルに無い時は `"auto"`。
- 画面を開いた時に `"auto"` なら、ブラウザの言語（`navigator.language`）が `ja` で始まれば日本語、それ以外は英語に決め、その値を設定に保存する（サーバーの返す文もこの言語で出すため）。
- 「せってい」の窓で切り替えられる。切り替えたらページを読み込み直す（描画中の文を差し替える仕組みは作らない）。
- 言語ごとの文は、使う場所のそばに日本語と英語を並べて書く（`tr("やどや", "INN")` のような小さな関数1つ）。翻訳ライブラリ・キーの一覧ファイル・複数形の仕組みは作らない。文の中に名前や数が入る物は、言語ごとに文をまるごと書く（語順が違うため）。
- `src/core` の文（ログの文など）は、言語を引数で受け取る純粋関数にする。

### 訳す範囲
- アプリ（`/`）と `terminal.html`：キャンバスの中の文（建物の札・題の札・名前以外の札・ほか n人 など）、窓・ボタン・ログ・でんれい・勇者のカード・コマンド・トースト・title 属性・placeholder・`<html lang>`。
- サーバーが返して画面に出す文（断った理由・失敗の文など）。設定の言語に合わせる。
- 勇者に送る文（さくせん の指示文）。英語の画面では英語で送る。
- モック（`/mock.html`）の、アプリと同じ部品とモックの偽のデータ（お知らせの文など）。モックのページ上部の開発用の説明文と `/art.html` は日本語のままでよい。
- ターミナルに出す起動時の案内・エラーは、今の英語と日本語の併記のまま（画面を開く前なので）。

### 英語の文の決まり
- 直訳しない。昔の英語版 JRPG のような、短く明るい文にする（例：「勇者1が 町に やってきた！」→「Hero 1 arrived in town!」、「勇者1を みおくりました。」→「You saw Hero 1 off.」）。説明口調にしない（「画面の文言」の節と同じ）。
- 建物の札・題の札など地図の中の短い札は大文字（INN / CHURCH / LIBRARY / ITEM SHOP）。ボタン・コマンドは先頭だけ大文字（Talk, Status, Follow…）。
- 主な言葉：でんれい＝Herald、ゆうしゃ＝Heroes、しゅつじん＝Embark、ターミナル＝Terminal、めいぼ＝Roster、ヘルプ＝Help、せってい＝Settings、ワールドマップ＝World Map、まち＝Town、▼ そとへ＝▼ Exit、フィールドへ＝To the field、そうげん＝Meadow、どうくつ＝Cave、よるのもり＝Night Forest。町の見た目：草原の村＝Meadow Village、海辺の港町＝Seaside Port、雪国の町＝Snow Town、砂漠のオアシス＝Desert Oasis、火山の町＝Volcano Town。
- 勇者のコマンド：はなす＝Talk、ようすを みる＝Status、ついていく＝Follow、そうび＝Equip、さくせん＝Tactics、にげる＝Flee、やすむ＝Rest、ターミナル＝Terminal、みおくる＝See off、たたかう＝Fight、めいれい＝Order、もどる＝Back。さくせん：ガンガンいこうぜ＝Go all out、いのちだいじに＝Play it safe、じゅもんせつやく＝Save MP。
- モンスター：スライム＝Slime、おばけ＝Ghost、ゴーレム＝Golem、ドラゴン＝Dragon。勇者の既定の名前「勇者N」＝「Hero N」。
- 英語は日本語より長くなりやすい。地図の中の札・コマンド窓・ログ4行・でんれいの行に収まらない時は、文を短くする（札を小さくしない）。

### 時刻
- 時刻は今もブラウザ（＝アプリを動かしている PC）のタイムゾーンで出している。アプリは自分の PC で動かして自分で見る物なので、**タイムゾーンを選ぶ設定は作らない**（PC の設定と同じ時刻が出るのが正しい）。
- 形式は言語に合わせる：日本語は今のまま（ログは `14:05`、報告・記録は秒まで `14:05:09`、めいぼの日付は `2026/10/14 14:05:09`）。英語も同じ所で同じ細かさの24時間（`14:05`・`14:05:09`）、日付は `Oct 14, 2026, 14:05:09`。
- 「◯分前」は英語で `5 min ago`・`2 h ago`・`3 d ago`、「いま」は `just now`。

### やらないこと（この段階）
- 3つ目以降の言語、ターミナルの起動時の案内の切り替え、`/art.html` とモックの開発用の説明文の英語化、PV の撮り直し（英語の画面ができてから別に行う）

## 公開前の直し：待ちと失敗を取り違えない（実装仕様・段階12）

開発の道具として見たレビュー（2026-10-14）で、「どの勇者が待っていて、何が失敗したか」を取り違える所が5つ見つかった。公開の前にこれを直す。見た目の演出は増やさない。

### 1. 許可待ちを何件でも持つ
- 今は許可待ちを全体で1件しか持たず、2人目の許可要求が来ると1人目はターミナルでの返事に戻される（`src/server/permissions.ts` の `PermissionWaiter`）。これを **許可の id ごと** に持つ。
- 1件ごとに、自分の期限（今と同じ120秒）・自分の終わり方（アプリでの許可・拒否・ターミナルで・期限切れ・本筋が進んだ）を持つ。ほかの許可の到着では終わらない。
- 本筋が進んだら解く決まり（同じセッション・同じサブエージェントの同じツールの終了、セッションの Stop）は今と同じで、その許可だけを解く。
- 同時に持つのは16件まで（ターミナルの上限と同じ）。それを超えた要求は、すぐターミナルでの返事にする。
- 画面を開き直した時は、待っている許可をすべて送り直す。画面がすべて閉じたら、すべてターミナルでの返事にする（今と同じ）。
- 答えは許可の id で届ける。もう終わった id への答えは何もしない（今と同じ）。

### 2. 急ぐお知らせは、どの町にいても出す
- 町の中（戦場・宿屋・教会も含む）でも、**許可・呼んでいる・とちゅうで たおれた** の3つは、ほかの町の分もでんれいに出す。今の町の分の下に「ほかの町」のまとまりで出し、押すとその町・勇者へ移る（今の動きと同じ）。新しい町・くるしい たたかい・報告は、今のとおり町の中ではその町の分だけ。
- でんれいのタブの件数も、町の中ではこの数（今の町の分＋ほかの町の急ぐ分）にする。
- 「とちゅうで たおれた」（新しい種類）：CLI がエラーで止まった（`StopFailure`）勇者。次の依頼を出すか、みおくるまで残す。並びは 許可 → 呼んでいる → とちゅうで たおれた → 新しい町 → くるしい たたかい → 報告。英語は「{name} went down」。音は今の失敗の音と同じ決まりで鳴らす。
- ゆうしゃのタブの一覧は今のまま（町の中ではその町の勇者だけ）。ただし、ほかの町の許可のカードは今のとおり出す。

### 3. 報告の見出しをうそにしない
- 今は、ファイルを書き換えていれば、テストが失敗していても「しょうり！ ファイル Nつを なおした」と出る。
- 一回の依頼の中で **最後に実行したテストの結果** を報告に持つ。見出しは次の順で決める：
  - `StopFailure` で終わった → 「とちゅうで たおれた…」／「Went down partway…」
  - 最後のテストが失敗 → 「ファイル Nつを かえた。テストは しっぱい」／「Changed N files. Tests failed」
  - ファイルを書き換えた（テストが無い・最後のテストが成功）→ 今の「しょうり！ ファイル Nつを なおした」／「Victory! Files fixed: N」
  - それ以外は今のまま（しらべて もどってきた／はなしかけてきた）
- 宝箱の絵・効果音は「しょうり」の時だけ。失敗・たおれた時は巻物と同じ見た目にする（宝箱を開けない）。
- 札の「テスト ○n ×n」は、テストのコマンドを実行した回数であることが分かる言葉にする（「テストの じっこう ○n ×n」／「Test runs ○n ×n」）。
- MP は、エージェントがコンテキストの量を知らせて来ない間は、100 ではなく「？」と出す（棒は灰色）。

### 4. 開き直しても勇者が消えない
- 今はサーバーが全員あわせて直近2000件のイベントしか残さず、よく動く勇者がそれを使い切ると、静かな勇者が開き直した画面から消える。
- 残し方を **勇者ごとの公平な上限** にする：全体の上限は今と同じ2000件のまま、あふれた時は、いちばん多く持っている勇者の古いイベントから捨てる。
- 勇者ごとに、次の物は捨てない：その勇者の最初のイベント（町に来たこと）、最後の `UserPromptSubmit`（今の依頼の始まり。報告の数を数え直すため）。
- 終わった勇者（`SessionEnd` 済み）のイベントは、今と同じく残り枠の中で古い順に捨ててよい。
- DB・ファイルへの保存・会話本文の永久保存はしない。画面の側の作り直し（`new Room()` から全部を当て直す）は今のまま。

### 5. 許可のコマンドを全部見せる
- 今は Bash のコマンドやファイルのパスを120文字で切り、切ったことも出していない。
- 許可の窓に出す中身を **2000文字まで** にする。窓の中では高さを決めて中でスクロールし、等幅の文字で折り返す。
- 2000文字を超えた時は、切ったことを窓に出し（「…（のこり N文字は ターミナルで）」）、**「はい」を押せなくする**（「いいえ」と「ターミナルで こたえる」だけ）。中身の分からない物を画面で許可させない。
- この全文は待っている間だけメモリに持つ。履歴（イベント）・ログ・ファイルには入れない（イベントの方は今の短い要約のまま）。
- 窓に残り時間を出す（「のこり 1:45」）。期限が来たら窓は消える（今と同じくターミナルでの返事になる）。

### やらないこと（この段階）
- git の画面、プレビュー、外出先からの確認（公開後に別の段階で）
- 「とめる」の確かめ方の変更、同じ名前の別リポジトリの区別、Codex の扱い（公開後）
- 見た目の演出の追加。PV の撮り直し（必要かどうかは直した後に決める）

## 返事のマークダウンを読める形で出す（実装仕様・段階13）

勇者（Claude Code・pi）の返事はマークダウンで書かれている。今は会話と報告の窓で、コードの囲み（```）以外がそのままの記号で出ていて、特に表が読みにくい。返事の本文を、マークダウンを解釈した形で出す。

### 対象
- 会話と報告の窓の、勇者の返事（報告の札の本文と、報告でない返事）。あなたの依頼の吹き出し・預かり表示・ログ・でんれい・勇者のカードは今のまま（文字のまま）。

### 解釈する記法（GitHub の書き方に合わせる。これ以外は文字のまま出す）
- ブロック：見出し（`#`〜`######`）、段落、空行、箇条書き（`-` `*` `+`）と番号付き（`1.`）、入れ子の箇条書き（字下げ）、チェックボックス（`- [ ]` `- [x]`）、引用（`>`）、コードの囲み（```、言語名は出さない）、区切り線（`---`）、**表**（`|` の列と `|---|:---:|` の行。そろえの指定も守る）。
- 行の中：太字（`**`・`__`）、斜体（`*`・`_`。英単語の中の `_` は斜体にしない）、打ち消し（`~~`）、コード（`` ` ``）、リンク（`[文字](URL)`）、URL そのもの。
- リンクは `http:`・`https:` だけをリンクにし、新しいタブで開く（`rel="noopener noreferrer"`）。ほかの形（`javascript:`・`file:`・相対パスなど）は文字のまま。画像（`![...](...)`）は読み込まず、代わりの文字をリンクと同じ扱いで出す。
- HTML のタグは解釈せず、文字のまま出す。

### 作り
- 解釈は `src/core` の純粋関数（文字列 → ブロックと行の中の部品の木）にし、テストを付ける。描画は web で DOM の要素と文字のノードを組み立てる。**`innerHTML` は使わない**（返事の中身を HTML として入れない）。
- マークダウンのライブラリは入れない。上の記法だけを、小さく素直に書く（1ファイル300行以内）。
- 解釈しきれない書き方（閉じていない `**`、列の数が合わない表など）でも、落ちずに文字として出す。表の列が足りない行は空のマスで埋め、多い分は捨てる。

### 見た目
- 今の窓の字（ドット絵の字）と色のまま。見出しは少し大きく金色、太字は明るく、コードは今の囲みと同じ背景の等幅、引用は左に線。
- 表は細い枠線のマス目にし、見出しの行は背景を少し明るく。窓より広い表は、表の中だけで横にスクロールする（窓は横に広がらない）。
- 箇条書きは「・」ではなく今の字に合う印（▸ など）でよい。字下げは入れ子の深さに合わせる。
- 英語の画面でも同じ。

### 1文字ずつの表示と「▼ つづき」
- 最新の返事の1文字ずつの表示は今のまま。解釈した後の **見える文字** を、文書の順に1文字ずつ出す（記号は数えない）。まだ文字が出ていないブロック（表の行・箇条書きの行など）は出さない。クリック・Enter で省略も今のまま。
- 長い本文の最初の部分（今は 420 文字・8行まで）は、解釈した後のブロックの単位で決める：入る所までのブロックを出し、表はその中の入る行まで（見出しの行は必ず出す）、コードの囲みは入る行まで。記法の途中で切れた記号が見えないようにする。

### やらないこと（この段階）
- 数式、脚注、HTML、画像の表示、コードの色分け、Mermaid、絵文字の短縮記法（`:smile:`）。依頼の吹き出しのマークダウン。
- **返事の中のファイルパスを開くこと（今後の課題）**：返事にはファイルパス（`src/web/rpg/talk.ts:42` など）がよく出るが、画面はブラウザなので、そのままでは手元のエディタやファイルを開けない。この段階ではパスは文字のまま（`file:` や相対パスのリンクも文字のまま）にする。開き方は後で決める。考えられる案：パスをコピーするボタン、エディタの URL（`vscode://file/...` など）を作る、サーバーに「このパスを開く」API を足して OS やエディタで開く（勇者の作業フォルダの中だけに限るなど、安全の決まりが要る）。

ADE の原則（`docs/ARCHITECTURE.md` の「原則：ハーネスではなく ADE」）を守って、次の順に足す。調査は `docs/ADE-RESEARCH.md`。

## 仕事の台帳と町の見分け方（実装仕様・段階14）

### 町をリポジトリで見分ける
- 町の正体（内部の鍵）を、リポジトリの共通の git ディレクトリ（`git rev-parse --path-format=absolute --git-common-dir` を実パスにした物）にする。git でないフォルダはそのフォルダの実パス。表示名は今のまま短い名前（本体の worktree のフォルダ名）。
- 同じ表示名の町が2つ以上ある時は、町の札・一覧で区別が付くよう、親フォルダ名を添える（例「app（client）」「app（personal）」）。
- 今の `towns.json` は名前で引いている。起動時に、保存してある path から鍵を求めて移す（求められない町は名前のまま残し、次にその町で勇者を出した時に直す）。勇者のイベントの `project` も、サーバーがセッションから鍵を引いて正しい町に入れる。

### 保存先：SQLite
- Node に組み込みの `node:sqlite` を使う（依存は足さない）。最低の Node を 22.13.0 に上げる（`package.json` の engines・`MINIMUM_NODE_VERSION`・README）。ファイルは `AGENT_CHARACTER_HOME/yushario.db`。
- 表は必要な分だけ：クエスト、クエストの出来事（依頼・報告の要点・状態の変化）、セッション（勇者の端末）とクエストの結び付き。スキーマの版を1つの数で持ち、起動時に順に上げる（移行の仕組みは関数の並び1つで足りる）。
- 町・設定・名前・めいぼの JSON はこの段階ではそのまま（無理に移さない）。

### クエスト（仕事）
- クエストは「勇者のセッションより長く残る仕事」。持つ物：id、町（鍵）、題、状態、作った時刻・更新した時刻、担当の勇者（セッション）、ためすこと（段階16）、拠点（段階17）、プレビュー（段階19）。
- 状態：`open`（まだ誰も）／`active`（勇者が取り組み中）／`waiting`（あなたの判断待ち：許可・呼んでいる・質問）／`review`（成果が届いて未鑑定）／`done`（あなたが採った）／`dropped`（やめた）。`done`・`dropped` は人だけが決める。ほかは出来事から決め、人も変えられる。
- 作り方：
  - 右の欄の新しいタブ「クエスト」の「＋ あたらしい クエスト」（題と、任意で目的の一文）。
  - 勇者に依頼を送る時（会話の窓・さくせん・ターミナルで直接打った依頼も）、その勇者に今のクエストが無ければ、自動で作って結び付ける（題は依頼の1行目の先頭60文字）。会話の窓の上に今のクエストの題を出し、「べつの クエストに する」で選び直せる（新しく作るのも選べる）。
- 1人の勇者は同時に1つのクエストに付く。勇者がいなくなってもクエストは残る。めいぼから呼び戻した勇者は前のクエストに戻る。
- 報告が届いたら、クエストの出来事に要点（報告の種類・見出し・変えたファイル名・テストの結果・時刻・かかった時間）を残す。

### 何を保存するか
- いつも保存する：クエストの題・目的・状態・時刻・担当・ファイル名・テストの結果・見出し。依頼の題（1行目の先頭60文字）。
- 「せってい」の「かいわも のこす」（既定は **のこさない**）を選んだ時だけ：依頼と返事の本文。選んでいない時は本文を保存しない。説明文に「題（依頼の1行目）は いつも のこります」と出す。
- 許可のコマンド全文・端末の出力・ツールの出力は保存しない。
- 「せってい」に「クエストの きろくを けす」（町ごと／すべて）。確かめてから消す。

### 画面
- 右の欄に3つ目のタブ「クエスト」（英 Quests）。町ごとのまとまり（町の中ではその町だけ、ワールドマップでは全町。でんれい・ゆうしゃと同じ決まり）。1行に：状態の印、題、担当の勇者、最後の更新（◯分前）。並びは waiting → review → active → open、done・dropped は「おわった クエスト」に畳む。
- 行を押すとクエストの札：題（直せる）、目的、状態（変えられる）、担当（押すとその勇者へ）、出来事の一覧（新しい順、報告は押すと会話の窓のその札へ）、保存した本文（ある時だけ）。
- 町の地図の掲示板（町にある赤い屋根の立て札）を押しても、そのクエストのタブを開く。
- サーバーを再起動しても、クエストと出来事は一覧と札に戻る（勇者の会話の窓は今のまま、メモリの分だけ）。

### API
- `/api/quests`（一覧・作成）、`/api/quests/:id`（読む・題・目的・状態の変更・消す）、`/api/quests/:id/assign`（勇者を付ける）。トークン必須（今の `/api/*` と同じ）。変化は WS `quests` で配る。

### やらないこと（この段階）
- 過去の CLI の履歴の取り込み、会話の窓をクエストの本文から作り直すこと、クエストの検索（一覧の絞り込みは町だけ）、町・設定の JSON の SQLite への移動。

## 成果の鑑定：差分を読む（実装仕様・段階15）

### 鑑定の窓
- 勇者の成果を、実際の git の差分で読む窓（会話の窓と同じく地図を覆う大きな窓）。題「{勇者} — かんてい」。
- 中身：勇者の作業フォルダの branch・HEAD の短い id・上流との差（↑n ↓n）、変更のあるファイルの一覧（変更・追加・削除・名前変更・未追跡、行の増減）、選んだファイルの差分（等幅、追加は緑・削除は赤の背景、行番号つき）。読むだけ。ステージ・コミット・元に戻す などは作らない。
- 入口：報告の札の「▶ かんてい」（ファイルを変えた報告の時）、勇者のコマンド「かんてい」、勇者のカード。窓の見出しに「▶ はなす」「▶ ターミナル」。
- 差分は開いた時と「▶ よみなおす」の時に読む（自動で読み続けない）。

### サーバー
- `/api/review?session=<id>`：そのセッションの作業フォルダについて、`git status --porcelain=v2 -z --branch`、`git diff --numstat` 等を `execFile`（引数の配列。シェルを通さない）で読んで返す。`/api/review/diff?session=<id>&path=<相対パス>`：1ファイルの差分。
- 対象は **サーバーが知っているセッションの作業フォルダだけ**（任意のパスは受けない）。path はそのフォルダの中だけ（`..`・絶対パス・シンボリックリンクで外へ出る物は断る）。
- git は `--no-ext-diff --no-textconv`、`-c core.quotepath=false`、色なし。時間は5秒まで、出力は1ファイル1MiBまで（超えたら「大きすぎて 出せない」）。バイナリは「バイナリの ファイル」とだけ出す。
- 未追跡のファイルは一覧に名前だけ出し、中身は押した時だけ（同じ上限）。`.env` 等の中身を勝手に出さないため。
- git でないフォルダ・git が無い時は「git の きろくが ない」と出す。

### ファイルを開く
- 鑑定の窓のファイル、報告の本文に出るファイルのパス（行の中のコードで、パスの形の物。`src/a.ts:42` の行番号も読む）に「ひらく」を付ける。押すと「せってい」で選んだエディタで開く：なし（パスをコピー）／VS Code（`vscode://file/<絶対パス>:<行>`）／Cursor（`cursor://file/<絶対パス>:<行>`）。相対パスは勇者の作業フォルダから絶対パスにする。エディタの選択はブラウザに覚える（localStorage）。
- これで段階13の「ファイルパスを開く（今後の課題）」を片付ける。サーバーに「開く」API は作らない。

### 「まだ ためしていない」
- ファイルを変えたのに、その往復でテストを1回も実行していない報告は「しょうり」にしない。見出し「ファイル Nつを かえた。まだ ためしていない」／「Changed N files. Not tested yet」、印は巻物と同じ（宝箱を開けない・勝利の音を鳴らさない）。テストが最後に成功した時だけ「しょうり」。
- クエストの状態は、ファイルを変えた報告が届いたら `review`（未鑑定）にする。鑑定の窓を開いたら札に「かんてい ずみ」の印（クエストの出来事にも残す）。

### やらないこと（この段階）
- 差分への書き込み・コメント・ステージ・コミット・push・PR、差分の自動の読み直し、エディタを開くサーバー API。

## 確かめた結果（実装仕様・段階16）

報告の「テスト ○n ×n」は、勇者がテストらしいコマンドを走らせた回数でしかない。クエストに「何を確かめれば良いか」と「どの状態の上で確かめたか」を持たせる。

### ためすこと（クエストの受け入れの条件）
- クエストの札に「ためすこと」の一覧を持たせる。1つは「名前」と「コマンドの形」（例：`型チェック` / `npm run typecheck`）。人が足す・消す。
- 町のリポジトリに `package.json` がある時は、その `scripts` の `test`・`typecheck`・`lint`・`build` を候補として出す（押すと足す。勝手には足さない）。
- Yushario 自身はコマンドを実行しない（原則2）。結果は勇者のツール実行（フック）から拾う。

### 証拠
- 勇者のコマンド（Bash 等）の実行が終わった時、そのクエストの「ためすこと」のコマンドの形を含む物、または今の分類でテストに当たる物を **証拠** として残す：コマンド（先頭200文字）、成功／失敗（PostToolUse／PostToolUseFailure）、時刻、勇者、そしてその時の **作業の状態の指紋**。
- 指紋：サーバーがその時に勇者の作業フォルダで `git rev-parse HEAD` と、未コミットの変更の要約（`git diff HEAD --no-ext-diff --no-textconv` と未追跡のファイル一覧のハッシュ）を取った物。git でないフォルダでは指紋なし（「じょうたい ふめい」）。git の読み取りは段階15と同じ決まり（execFile、時間・出力の上限）。
- 証拠は SQLite のクエストの出来事に残す（本文の保存の設定に関係なく。コマンドの先頭200文字は保存してよい物に入れる）。

### 印
- ためすこと1つごとの印：**みじっこう**（証拠なし）／**ごうかく**（最新の証拠が成功で、指紋が今と同じ）／**しっぱい**（最新の証拠が失敗）／**ふるい**（最新の証拠は成功だが、その後に作業の状態が変わった）。今の指紋は、クエストの札・鑑定の窓・報告の札を開いた時と、勇者の Stop の時に取り直す。
- クエストの札・クエストの一覧の行・報告の札に、印を並べて出す（例「型チェック ✔ ・ テスト ✖ ・ ビルド ・」）。押すと証拠（コマンド・時刻・勇者・HEAD の短い id）を出す。
- 「おわった（done）」にする時、ためすことに ごうかく 以外があれば、確かめの一言を出す（止めはしない。人が決める）。
- 報告の見出し（段階15）の「しょうり」は今のまま（その往復の最後のテストが成功）。クエストの合格はこの印で別に見せる。

### やらないこと（この段階）
- Yushario がコマンドを実行すること、CI・PR のチェックの取り込み、shell のセッション（フックが無い）での実行の取り込み。

## 遠征拠点：worktree（実装仕様・段階17）

### 出陣の行き先
- 「しゅつじん」の窓の行き先に、今の選択肢に加えて：
  - **この町の 拠点**：そのリポジトリの既存の worktree（`git worktree list --porcelain`）を、branch 名つきで並べる。
  - **あたらしい 拠点を つくる**：もとにする branch（ローカルの branch の一覧。既定は今の HEAD の branch）、新しい branch 名（既定 `yushario/<クエストの題から作った短い名前>`、直せる）、置き場所（既定 `<リポジトリの親フォルダ>/<リポジトリ名>.worktrees/<branch 名の / を - にした物>`、直せる）。
- 作る時は `git worktree add -b <branch> <path> <base>` を execFile で。branch 名は `git check-ref-format --branch` で確かめ、既にある branch・既にある置き場所は断る。リポジトリの中の準備のスクリプトの実行、`.env` などのコピーはしない（「じゅんびは ターミナルで」と一言出す）。
- クエストから出陣した時（クエストの札の「▶ しゅつじん」）は、そのクエストに拠点（path と branch）を結び付ける。以後そのクエストの勇者は既定でその拠点へ出る。

### 町での見え方
- 拠点は同じ町の中（町はリポジトリで見分ける：段階14）。勇者の名札・カード・クエストの行に branch 名を小さく出す。ゆうしゃのタブで、勇者を拠点（branch）ごとにまとめて出せる（切り替え）。

### 同じ場所に2人
- 書き換える勇者がいる作業フォルダに、もう1人を出そうとした時は「{勇者}が この ばしょで さぎょうしている。おなじ ファイルを かきかえる かもしれない」と出し、「あたらしい 拠点を つくる」を勧める（止めはしない）。ここでの「書き換える勇者」は、そのフォルダで動いている hero の勇者（読むだけの役は段階18で決める）。

### 拠点を たたむ
- クエストの札・しゅつじんの窓の拠点の行に「たたむ」。そこに勇者がいない、変更が無い（`git status` が空）時だけ `git worktree remove <path>`（`--force` は使わない）。branch は消さない。変更がある時は「へんこうが のこっている」と断る。

### やらないこと（この段階）
- 拠点の中の準備（依存のインストール・ポートの割り当て）、branch の削除、merge・rebase・PR、拠点を別のリポジトリへ。

## パーティーと引き継ぎ：協調（実装仕様・段階18）

原則3・4が特に効く段階。Yushario は役割・指示・引き継ぎを **保存し、届け、見せる** だけ。何をさせるか、どう分けるかは人か指揮役の勇者が決める。

### パーティー
- クエストに勇者を何人でも付けられる（今は1人）。それぞれに **役割**：じっそう（実装）／レビュー／しらべ（調査）／ためし（検証）／しき（指揮）。役割は自由な一言も足せる。
- **書き換える役** はクエストに1人だけ（既定は最初の じっそう）。札で付け替えられる。
- 役割を付けた時、その勇者に送る **役割の紹介文** の下書きを出す（例「あなたは このクエストの レビュー役です。ファイルは かきかえず、気づいたことを ほうこくしてください。」）。人が直して送る（送らないのも選べる）。Yushario が勝手には送らない。
- 書き換える役ではない勇者が、その往復でファイルを変えた時は、でんれいに「{勇者}が やくわりの そとで ファイルを かえた」（クエストにも残す）。止めはしない（CLI の中は変えない：原則5）。
- クエストの札に「パーティー」：勇者・役割・状態・拠点。そこから「▶ はなす」「▶ かんてい」、仲間を足す（今いる勇者を選ぶ／新しく出陣）。

### 引き継ぎの巻物
- クエストの札の「ひきつぎ」で、別の勇者（今いる・新しく出陣）に仕事を渡す。巻物の下書きを Yushario が **台帳の事実だけで** 組み立てる：クエストの題・目的、ためすことの印、変えたファイル、拠点（path・branch）、最後の報告の見出し（本文を残している時は最後の返事の本文）。要約や推測は作らない（原則1）。
- 「まとめを たのむ」で、今の担当に定型の依頼（「ひきつぎの まとめを かいてください：目的・きめたこと・のこり・注意」）を送り、届いた返事を巻物に差し込める。
- 人が巻物を読んで直し、「わたす」で相手に送る。書き換える役を移すかも選ぶ。送った巻物はクエストの出来事に残す（本文の保存の設定に従う）。

### 指揮役の勇者と管理の道具
- クエストで **しき（指揮）** の役を付けた勇者だけが、管理の道具でパーティーを動かせる。指揮役はクエストに1人。
- 管理の道具：コマンド `yushario quest …`（今の bin に足す。中身はサーバーの API を呼ぶだけ）。サーバーは勇者の端末に、そのセッションだけの合言葉（`AGENT_CHARACTER_AGENT_TOKEN`）と道具の場所を渡す。画面用のトークンは渡さない。
- できること（指揮役）：自分のクエストを読む（題・目的・ためすことの印・パーティー・出来事の要点）、パーティーの勇者に依頼を送る（会話と同じ道。作業中は預かる。受け手の会話の窓に「しき {勇者}から」と出し、クエストに残す）、仲間を呼ぶ・役割を付ける（**でんれいで人の確かめが要る**。人が「はい」と言った時だけ出陣・付け替え）、クエストに覚え書きを足す、状態を `review` にする。
- できること（ほかの勇者）：自分のクエストを読む、覚え書きを足す。
- できないこと：`done`・`dropped` にする、クエストを消す、許可に答える、ほかのクエスト・ほかの町に触る、画面と同じ全部の API。
- 合言葉はセッションが終わったら使えない。道具の出力は短い JSON と人が読める文の両方（`--json`）。
- 指揮役に渡す定型の紹介文（人が直して送る）に、道具の使い方を数行で入れる。

### やらないこと（この段階）
- 自動の分解・自動の割り当て・依存の図・予定の実行、勇者同士の直接の会話（必ず Yushario を通り、人に見える）、別のクエスト・町をまたぐ指揮、Orca など外の協調の仕組みとのつなぎ。

## プレビュー：同じブラウザのタブとつなぐ（実装仕様・段階19）

Yushario はブラウザで動くので、開発中のページを Yushario の中に埋め込むのではなく、同じブラウザの **別のタブ** として開き、つなぐ。

### プレビューの URL
- クエスト（無ければ町）に、プレビューの URL を何本でも結び付ける：名前（任意）と URL。URL は `http://localhost:*`・`http://127.0.0.1:*`・`http://[::1]:*` だけ（https も同じホストなら可）。Yushario 自身のポートは断る。
- 候補：勇者・shell のターミナルの出力に出たローカルの URL（`Local: http://localhost:5173/` など）をサーバーが拾い、クエストの札に「みつけた URL」として出す（押すと結び付ける。勝手には結び付けない）。
- クエストの札・勇者のカード・クエストの一覧の行に「▶ みる」。押すと `window.open(url, "yushario-preview-<クエストid>")` で、そのクエスト専用のタブで開く（2回目からは同じタブに切り替わる）。

### ページからの知らせ（選んだ人だけ）
- 開発中のページに、Yushario が配る小さなスクリプトを1行足すと（`<script src="http://127.0.0.1:<Yushario のポート>/preview-link.js"></script>`。札に「つなぐ 一行」をコピーするボタン）、そのページは Yushario のタブ（`window.opener`）に、今の URL・題・ページのエラー（`error`・`unhandledrejection`・`console.error` の先頭）を `postMessage` で知らせる。
- Yushario は、結び付けた URL と同じ origin からの知らせだけ受ける。クエストの札とプレビューの印に「エラー n」を出し、押すと一覧。「勇者に つたえる」で、エラーの一覧を入れた依頼の下書きを会話の窓に入れる（人が直して送る：原則3）。
- スクリプトは知らせるだけで、ページを変えない・操作しない・外へ送らない。`preview-link.js` は配る静的ファイル（トークン不要）。

### やらないこと（この段階）
- Yushario の中への埋め込み（iframe）、ページの中身の読み取り・自動操作・画面写真、ブラウザの拡張機能、外の URL のプレビュー。

## 公開前の直し2：なりすましと誤った合格を無くす（実装仕様・段階19.5）

公開前のレビュー（5つの観点。まとめは作業記録の `review2/SUMMARY.md`）で見つかった A と B を直す。新しい機能は足さない。

### 守る範囲（脅威の前提）
- Yushario と勇者は同じ OS 利用者で動く。勇者が本気で悪意を持てば、利用者と同じことができる（ファイル・DB を直接書くなど）。これは防げない。
- 防ぐのは、**HTTP を1回送るだけで、ほかの勇者・人のふりができる** こと。役割・所属・証拠・許可は、サーバーが自分で起動した端末と、その端末だけの合言葉に結び付けて決める。
- この前提を `docs/ARCHITECTURE.md` の原則の近くに数行で書く。

### 1. 勇者の知らせ（フック）の合言葉
- アプリから起動した端末のフック（Claude Code のコマンドのフック、pi の拡張、許可の HTTP フック）は、端末ごとの合言葉（今の `AGENT_CHARACTER_AGENT_TOKEN`）を付けて送る。許可の HTTP フックにヘッダーを付ける方法は Claude Code の公式の設定（http フックのヘッダーと環境変数）で確かめる。確かめられなければ、許可もコマンドのフック経由にする。
- サーバーは合言葉から端末を決め、本文の `terminal` は信じない。合言葉の無い・合わない知らせは **観て描くだけ**（外で動かしている Claude Code が町に来る、は残す）：台帳・パーティー・ためすことの証拠・合言葉の失効・許可待ちの端末への結び付けには使わない。
- フックの入口は `Origin` 付きの要求を断る（CORS も返さない）。
- 勇者が「再開した」（SessionStart）と言っただけで、ほかの端末の所属を移さない。所属を移すのは、人が画面で「よびもどす」を選び、サーバーが起動した再開の端末で、もとの端末がもう終わっている時だけ。

### 2. git の設定にあるプログラムを走らせない
- サーバーが走らせる git（鑑定・指紋・状態・worktree）は、`core.fsmonitor`・hooks（`core.hooksPath`）など、repo の設定にあるプログラムを走らせない形にする。止められない物があれば仕様に書く。
- 実装は fsmonitor・hooks・外部 diff・textconv と、列挙した filter の clean／smudge／process を無効化する。拠点は filter 変換なしで作るため、その準備は人が端末で行う。global／system 設定と継承 `GIT_*` は使わない。同一 OS 利用者による `.git/config` の同時差し替え、PATH の git 自体の改変を防ぐ sandbox ではない。

### 3. ためすことの「今の指紋」
- 比べる先は、クエストに保存した拠点（無ければ、その時の書き換える役の端末のフォルダ）。ほかのセッションで代わりにしない。読めなければ「ふめい」で、合格にしない。
- 証拠にも、その時の拠点を残す。拠点が違う証拠は今の合格に使わない。
- 未追跡のファイルは、名前だけでなく中身も指紋に入れる（大きさに上限。中身は保存も配信もしない。上限を超える・読めない時は「ふめい」）。
- 遅れて届いた指紋の書き込みは、元の証拠（クエストも一致）にだけ入れる。消したクエストには入れない。

### 4. パーティーの状態と配送
- クエストの状態は、メンバーのだれか1人でも人の判断を待っていれば「判断待ち」。ほかの仲間の動き・報告で消さない（`done`・`dropped` を人だけが決める決まりはそのまま）。
- 会話に対応しない勇者（shell・Codex）へのパーティーの依頼・紹介文・巻物は、預からずに理由を付けて断り、画面では選べない・「ターミナルのみ」と出す。
- プレビューの「勇者に つたえる」の宛先は、今の書き換える役（いなければ人がパーティーから選ぶ）。役割の付け替えで入口を消さない。
- 消したクエスト・終わったセッションの覚え（Map・Set）を片付ける。

### 5. 画面
- 狭い窓（800幅・縦長・125%）でもサイドバーのタブと中身に届く。長い名前・branch は町の絵の上で省略。長いクエスト題は札・会話で折り返す。クエスト一覧の日付は折り返さない。開いたコマンドの窓は、窓の大きさが変わったら範囲の中に置き直す（閉じてもよい）。鑑定の「よみなおす」は折り返さない。
- 札の書きかけ（題・目的・ためすこと）は、裏の更新で消さない。

### 6. 初めての人・キーボード・エラー
- 空の町とヘルプに、仕事の流れを短く：しゅつじん → 依頼 → 報告 → 鑑定・ためすこと → クエストを おえる。HP・MP・Lv とクエストの言葉の対応も数行。
- 設定などの窓は、開いたらフォーカスを窓に移し、閉じたら戻す。地図だけにある入口（眠る町・しまった町）に、キーボードで届く入口も置く。
- DB が開けない・壊れている時、DB の場所と「消さずに退避して、別の `AGENT_CHARACTER_HOME` で切り分け」を日英で出す。勝手に消したり作り直したりしない。
- 出陣の窓で、会話に対応しない CLI を選んだら「ターミナルのみ（勇者は出ない）」と出す。
- 英語の README を今の英語の画面に合わせる。

### やらないこと（この段階）
- コミット済みの成果の鑑定、端末を閉じた後の鑑定（次の段階）、外からの接続、OS 利用者を分けた隔離、クエストの一覧のページ分け。

## 公開前の仕上げ：残りの課題を片付ける（実装仕様・段階20）

## 最終チェックの直し（実装仕様・段階20.5）

最終チェック（`review3/SUMMARY.md`）の A・B・C をすべて直す。新しい機能は足さない。

### 1. ためすことの合格を、走ったテストの成否だけにする
- フックの成功（終了 0）を、ためすことの成功として使えるのは、コマンドが **そのテストのコマンドだけ** で、勇者の拠点のフォルダで走った時だけ。`&&` の並びも「ふめい」にする（`cd 別の場所 && npm test` は別の場所を試し、`npm test && cp …` は試した後にコードを変える）。フックが知らせるフォルダ名が拠点と違う時も「ふめい」（Claude Code は Bash の `cd` を次の呼び出しへ持ち越す）。
- `||`・`;`・`|`・`&`・改行・`( )`・`$( )`・バッククォート・`if` などを含む時は、テストが走ったか・成功したかが分からないので「ふめい」（合格にも失敗にもしない）。失敗（終了 0 以外）も、同じ条件の時だけ「しっぱい」にする。
- 万能なシェルの解析は作らない。引用符の中の文字は今までどおり数えない。

### 2. 止まった・終わったの知らせを正しく
- pi の拡張は、中断が終わった時に `InterruptConfirmed` を送る（Codex と同じ）。
- 古い `SessionEnd`（その端末の一番新しい知らせより前の時刻）では、画面を「おわった」にせず、台帳の往復も消さない。
- 同じ仲間の ID がもう一度使われた時、前の世代の Stop で新しい仲間を消さない。
- 動いている間の警告の本文・許可の音の既知の ID に上限を付ける。

### 3. 量
- 証拠・報告リンクの読み取りと配信は、画面に要る分だけ（札を開いた時に詳しく読む）。保存件数に比例して毎回増えない。

### 4. プレビューの宛先
- 書き換える役の端末が終わっていたら、会話できるほかの仲間から人が選べる。終わった端末は候補に出さない。

### 5. 画面とキーボード
- クエスト一覧が更新されても、キーボードのフォーカスを保つ。出陣の窓を開いた直後のフォーカスは窓の中に置く（読み込みが終わった後も）。
- サーバーの再起動で古い画面の合言葉が合わなくなったら、「サーバーが 起動しなおした。ターミナルに出た 新しい URL を ひらいて」と日英で出す。
- 鑑定の窓の長い題を折り返す。「比べる元」の欄を縦に潰さない。

### 6. 決まりと文書
- テストは src/core の振る舞いに絞る決まり（AGENTS.md）に合わせ、今ある server のテスト（`permissions.test.ts`・`pty-session.test.ts`）は、純粋な部分を src/core に移してそこでテストする。移せない物は ARCHITECTURE.md に例外として理由を書く。
- `docs/OBSERVATION.md` とコメントの古い決まりを今の形にする。

## 鑑定の判断と、成果を うけとった記録（実装仕様・段階21）

ADE の再評価（`docs/ADE-REVIEW.md` の指摘4）への対応。差分は読めるが、「どこを直してほしいか」「どの版を見て、どう判断したか」「何を受け取ったか」が残らない。これを残す。Git の操作（PR の作成・push・merge）と CI の取得は作らない。

### 1. 窓を開いた記録と、判断の記録を分ける
- 鑑定の窓を開いた時に残す出来事の名前は「かんていを ひらいた」にする（全部読んだ・承認した、という意味にしない）。
- 鑑定の窓に「▶ みとめる」「▶ なおしが いる」を置く。押すと、サーバーがその拠点の branch・HEAD・作業状態の指紋（ためすことと同じ物）を取り、比べた物（未コミット／ブランチ全体と比べる元）と一緒に、クエストの出来事「判断」として残す。指紋が取れない時も残すが「じょうたい ふめい」と出す。
- API：`POST /api/review/verdict`（合言葉、`session` か `quest`）。本文 `{ verdict: "approved" | "changes", mode, base? }`。拠点の選び方は鑑定の読み取りと同じ。

### 2. 差分の場所から、なおしてもらう
- 差分の行番号を押すと、その行を選ぶ（もう一度押すと外す。複数可）。
- 「▶ えらんだ所を なおしてもらう」で、ファイル・行番号・その行の中身・比べた物・HEAD を会話の下書きに入れる。送るのは人（自動では送らない）。会話できる勇者がいない時はボタンを出さない。

### 3. うけとる（採った）時の記録
- クエスト札で状態を「採った」にする時、理由（任意・500文字まで）と PR の URL（任意・`https://` だけ・500文字まで）を書ける。
- API：`POST /api/quests/:id/adopt`（本文 `{ reason?, pr? }`）。サーバーが拠点の branch・HEAD・指紋と、その時のためすことの印を取り、出来事「うけとった」として残してから、状態を「採った」にする。拠点が無い時も残すが、HEAD は空。
- 札は一番新しい「うけとった」の記録（HEAD・理由・PR へのリンク）を出し、「採った ＝ main への とりこみ では ない」と添える。PR のリンクは別のタブで開く。

### やらないこと
- PR の作成・push・merge・CI の結果の取得。行ごとのコメントのやりとり。判断による採用の強制（判断が無くても採れる）。

### 4. クエスト札は、まず状況と次の一手を見せる（ADE-REVIEW の指摘5）
- 札の上には、状態と「いま必要なこと」（例：成果を かんていしよう）、目的、担当と拠点、ためすことの印、よく使う操作（かんてい・はなす・採る・しゅつじん）、最新の うけとった記録か報告を出す。
- 「採る」は状態の選択肢とは別のボタンにする。押すと編集を開き、状態を「採った」にして理由の欄へ移る（保存は人が押す）。
- 編集（題・目的・状態・拠点を たたむ・けす）、ためすこと・プレビューの追加、パーティーと ひきつぎ、できごとの全件は畳む。パーティーは、仲間が加わったか巻物を渡したことがあれば、初めから開く。開いた欄は、札が描き直されても開いたままにする。
- 機能は足さない・消さない。並べ方だけを変える。

## クエストを流れで見せる（実装仕様・段階22）

段階21の4（札の並べ替え）では、「このクエストが流れのどこにいるか」「新しい勇者が割り当てられたか」が分からなかった。画面の見本で合意した形に作り直す。保存するデータの形は変えない。

### 流れ
- はじめる：1 依頼を書く → 2 勇者に任せる → 3 指示を送る → 4 勇者が作業。報告のあと：5 報告と変更を見る → 6 受け取る、または なおしてもらう（4 に戻る）。合格条件は 1〜3 のどこで足しても、足さなくてもよい。
- 段階は保存している状態と担当から読む（`src/core/quest-stage.ts`）。担当なしの準備中は「任せる」、担当ありの準備中は「指示を送る」、作業中・返事待ちで担当がいない時も「任せる」。
- 新しい勇者に任せた時、前の勇者の「作業中・返事待ち」を引き継がず、準備中に戻す（新しい勇者には まだ何も伝わっていない）。指示が届けば、今までどおり作業中に進む。

### クエストのタブ（一覧）
- 町ごとではなく「あなたの番／勇者が作業中／おわった（畳む）」に分ける。各行に段階の札（橙＝あなたの番、青＝勇者の番）、担当の勇者、町、branch を出す。町の中では、その町のクエストだけを出す（今まで通り）。

### 札
- 上から：6段階の帯 → 「次にやること」（段階ごとに1つ。主なボタンは1つ）→ 担当（交代したら「前 → 今」）・作業する場所・目的・合格条件・何回目 → 畳んだ欄（依頼と目的の書きかえ・けす／合格条件とプレビュー／パーティーと引き継ぎ／これまでの出来事）。
- 任せる：町にいる勇者を選んで任せる、または新しく出陣させる。指示を送る：依頼の文を見直して送る。その時、町の package.json の合格条件の候補を選んで足せる。報告を見る：最新の報告と合格条件の印、「変更を見る（かんてい）」「受け取る」「なおしてもらう（話す窓）」。

### 新しいクエストの窓
- 町・依頼（1行目がクエストの名前）・任せる勇者（町にいる勇者／新しく出陣させる／まだ決めない）。主なボタンは「▶ 作って依頼する」（出陣を選んだ時は「▶ 作って出陣させる」）。「作るだけ」も残す。

### 言葉
- RPG の言葉は名前・見出し・雰囲気に使い、ボタンと「次にやること」には押すと何が起きるかを普通の言葉で書く。かんてい→変更を見る（かんてい）、採る→受け取る、ためすこと→合格条件、ひきつぎの巻物→引き継ぎのメモ（巻物）、拠点→作業する場所。

### 調整（段階22.1）
- 「受け取る」は「採用する」に言いかえる（流れの言葉に合わせる）。
- 「クエストを消す」は畳まずに、札の右上と一覧の各行に出す。消す前に確かめる。
- 報告を見る段階のボタン：「変更を見る（かんてい）」「報告を受ける」（話す窓の その報告を開く）「採用する」「やり直してもらう」（札の中で新しい指示を書いて送る。送ると次の回の作業になる）。

## パーティー編成の窓（実装仕様・段階23）

パーティーの仲間は、別々に起動した CLI セッション（別の勇者）。サブエージェントではない。役割は名札と紹介文が変わるだけで、効いているのは「担当（書きかえる役）は1人」と「しき役は1人で、新しい仲間・役の変更は人の承認を待つ」の2つ。これが見えるように作り直す。

### 札
- 「パーティー」は畳まずに、仲間の一覧（名前・担当 ✎／手伝い／しき・状態）と「▶ パーティーを へんせいする」だけを出す。

### 編成の窓（ドラクエのパーティー編成を参考にする）
- 黒い窓に白い二重の枠、選んでいる行に ▶。左「いまの パーティー」、右「町に いる 勇者」（＋ 新しく 出陣させる）、勇者を選ぶと出るコマンドの窓、手順を進めるメッセージの窓。
- 町の勇者を選ぶ：「手伝ってもらう」（何を頼むか：調べる／レビュー／テスト → 伝える文。文の頭に役目の説明が入る → 頼む）、「担当を 交代する」。
- 仲間を選ぶ：はなす・変更を見る・担当を 交代する（手伝いの時）・しき役に する／やめる・パーティーから 外す。
- 担当を交代する：引き継ぎメモ（巻物）、前の担当に まとめを 書いてもらう・届いた まとめを 入れる、前の担当を「そのまま 残す（手伝いに なる）／みおくる」、作業中なら止まらないと知らせる → 交代して メモを送る。
- 役の呼び名：担当・レビュー・調べる・テスト・しき。紹介文だけを送る操作はなくす（頼む文に含める）。

### サーバー
- パーティーから外す（`DELETE /api/quests/:id/party?session=`）。勇者そのものは町に残る。
- 担当を移すと、前の担当は手伝い（調べる）になる。クエストの担当は、書きかえる役の勇者を指す。

### 調整（段階23.1）：勇者の絵と装備を見せる
- 編成の窓は、パーティーを大きなカード、町にいる勇者を小さなカードで並べる（ソシャゲの編成画面のように）。カードには町と同じ色の勇者の絵、名前、役、CLI と Lv、モデルと effort、MP、状態を出す。最後に「＋ 仲間を 足す」「＋ 新しく 出陣させる」の枠を置く。
- モデルと effort は、出陣の時に選んだ装備（ぶき＝モデル、アクセサリ＝effort）と、アプリで替えた装備から出す。装備なしで出陣した時や CLI の中で替えた時は分からないので「不明」と出す（推測しない）。
- 右の「ゆうしゃ」タブの各行にも、同じ「モデル · effort」を出す。

### 調整（段階23.2）：採用した回答を残す・仲間の居場所を分ける・作る時に編成する
- 採用する時、その回の報告の本文（最後の返事）を、採用の記録に残す。「かいわも のこす」が切れていても残す（人が「採用」を選んだ回答だけ）。そのことは「採用する」の欄に書き添える。採用したクエストの札は、会話の窓に飛ばずに、採用した回答（Markdown）・報告の要点・版・PR・理由を出す。
- 編成の窓は、仲間を「いまの パーティー」と「町を 去った 仲間（よびもどせる・薄く）」に分ける。端末は動いているが町に来ていない勇者（Codex が最初の依頼を待つ時など）は、理由を出す。名前が分からない勇者は ID ではなく「去った勇者」。同じ名前の勇者は、CLI が違う時だけ CLI を添える。
- 新しいクエストの窓に「作って パーティーを 編成する」を足す。担当に依頼を送ってから、編成の窓を開く。

## パーティーの作戦と 編成の決まり（実装仕様・段階24）

パーティーを組んだら、勇者どうしが決まった流れで連携して動けるようにする。その流れを「作戦」と呼び、クエストごとに1つ選ぶ。利用者と合意した仕様（2026-10-16）。

### すべての作戦に共通
- 担当（書きかえる役）は1人だけ。実装を2人で分けたい時は、クエストを2つに分ける。
- 役は 担当・レビュー・調べる・しき の4つ。「テスト」役は新しく選べない（前に入れた勇者は名札だけ残る）。
- 手伝い（レビュー・調べる）は書きかえない。採用は必ず人。新しい仲間・役の変更も人が決める。
- 作戦が自動で送った文は、すべてクエストの出来事に残す（「作戦から ○○へ」）。止まった時は理由を残す。
- 「命令に従え」に戻すと、その場で自動の送信が止まる（作業中の勇者はそのまま終わるまで続く）。作戦を変えられるのは、自動の送信が止まっている時だけ。
- 作戦で動く手伝いは、作戦ごとに最大3人（入った順）。それより多い仲間と、作戦が使わない役の仲間は「作戦の外」で、頼まれた時だけ動く。

### 作戦
- **命令に従え**（はじめ）：自動の送信なし。いつでも選べる。
- **レビューし合え**：担当1人とレビュー1〜3人。レビュー役は担当と同じ作業フォルダで出陣していること。担当が報告したら、作戦の中のレビュー役全員に「この変更をレビューして」を送る（最後の行に「判定：OK／判定：要修正」を書くよう頼む）。全員の判定がそろったら、1人でも要修正なら指摘をまとめて担当に差し戻す（次の回）。全員 OK なら「報告を見よう」と出来事に残して止まる。差し戻しは3回まで。人が担当に新しく頼むと、回数は1からやり直し。
- **調べてから**：担当1人と調べる1〜3人。人の依頼を、まず調べる役全員に送る（各自の「ひとこと」を観点として添える）。全員の報告がそろったら、報告を依頼に添えて担当に送る。調べるのは最初の1回だけ。
- **全部任せた**：しき1人と、しきとは別の担当1人。しき以外の仲間が報告したら、その報告をしき役に届ける。誰に何を頼むかはしき役が決める（`yushario quest send`）。

### 止まって人に返す時
- レビューし合え：判定が読めない／回数の上限／担当かレビュー役が倒れた（失敗の報告）／担当が町を去った／頼めるレビュー役がいない。レビュー役が去った時は判定から外し、0人になったら止める。
- 調べてから：調べる役が倒れた／誰も返事をしなかった。

### API
- `GET /api/quests/:id/tactic`：作戦・編成の合否（足りない役、作戦の中・外）・進み具合（回・判定待ちの人数・止まった理由）。
- `POST /api/quests/:id/tactic` `{tactic}`：作戦を選ぶ。足りない時と、進んでいる最中（「命令に従え」以外へ）は断る。
- `POST /api/quests/:id/research` `{text}`：調べてからを始める。

### 画面
- 編成の窓の上に「さくせん」を置き、4つから選ぶ。選べない作戦は灰色で、足りない役を出す。作戦の外の仲間のカードに「作戦の外」。
- クエストの札に、いまの作戦と回を出す（一覧には まだ出さない。一覧を出すたびに作戦を読むと重くなるため）。進んでいる間、札の「次にやること」は「作戦で 進んでいる（判定 1/2）」と出し、「止める（命令に従え に戻す）」を置く。止まった時は理由を出す。
- 調べてからの時、指示を送るボタンは「調べる役に 送る」になる。
- 札の「報告」と、採用した時に残す回答は、担当（全部任せた なら しき役）の報告を使う。レビュー役・調べる役の返事は、クエストの答えにしない。

### 調整（段階24.1）：編成してから依頼する
- 新しいクエストの窓の「作ってパーティーに依頼する」は、クエストを作って担当を決めるだけで、依頼は送らない。編成の窓の下に「依頼（編成が 終わったら 送る）」を出し、仲間・作戦を決めてから「▶ 編成を終えて 依頼する」で担当に送る（作戦が 調べてから なら 調べる役に送る）。新しく出陣して戻った時も、書きかけの依頼を引き継ぐ。
- 担当がいない時に町の勇者を選ぶと「担当にする」（何も送らずに担当に決める）を出す。
- 作戦が読めない時（サーバーが古い時など）も、仲間の一覧は出す。作戦の欄には読めない理由を出す。

### 調整（段階24.2）：出陣を始めた場所に戻る
- 画面上部の「しゅつじん」：今までどおり、町に着いたら会話の窓を開く。クエストには割り当てない。
- クエストの札の「新しく出陣させる」（担当がいない時）と、新しいクエストの窓の「作って出陣させる」：新しい勇者を担当にし、会話の窓ではなくクエストの札に戻る（「指示を送る」の段階）。
- 編成の窓の「＋ 新しく 出陣させる」：クエストには割り当てない。編成の窓に戻り、新しい勇者を選んだ状態にする（役は窓の中で人が決める）。書きかけの依頼は残す。町に着くまでは「町に 向かっている」と出し、名前は出陣したフォルダの名前で出す。
- ターミナルで最初の依頼を送る勇者（Codex など）は、どこから出陣しても今までどおりターミナルを開く。

### 調整（段階24.3）：町を去った仲間
- 編成の窓で、町を去った仲間は「町に いる 勇者」の下の段に、絵を出さずに1行で出す：名前・HP・MP・モデルと effort。名前・装備は「めいぼ」に残った物を使い、HP・MP は分からなければ「？」。
- 選ぶと、めいぼに載っていれば「よびもどす」（前の会話の続きから再開し、町に着くと元の役でパーティーに戻る）、載っていなければ呼び戻せない理由を出す。どちらでも「パーティーから 外す」を出す。
