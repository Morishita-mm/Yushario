# ドット絵の作り方（町のコンポーネント）

町の絵は、オブジェクトを **単品のコンポーネント** として作り、画面で組み合わせる。
各コンポーネントの画像は Codex の画像生成（`$imagegen`、gpt-image-2）に任せ、生成後に機械的に「本物のドット絵」へ整える。

## 流れ

1. `tools/art/components.json` … コンポーネントの一覧（大きさ・コマ・指示文）。修正はここを直して作り直す。
2. `node tools/art/generate.mjs [id ...]` … Codex に1コンポーネント1枚ずつ生成させる（`.art-work/raw/<id>.png`、コミットしない）。
   勇者の設定画（`hero-model`）を先に作り、勇者の各ポーズと仲間はそれを **デザインの参照画像** にして作る（見た目のぶれを防ぐ）。
3. `uv run --with unfake --with pillow --with numpy tools/art/pack.py [id ...]` … 生成画像を整える。
   - [unfake](https://pypi.org/project/unfake/) でドットの大きさとグリッドを検出し、ブロックごとの代表色で縮小、ジャギー掃除。
   - 色は全コンポーネント共通のパレット **Resurrect 64**（`tools/art/resurrect-64.hex`）に合わせる → 部品を並べても色がなじむ。
   - 緑の背景を透明にし、コマを切り出して同じ大きさのセルに並べ直す（足元をそろえる）。
   - 出力：`public/art/<id>.png` と `public/art/manifest.json`。
4. `/art.html` のギャラリーで1つずつ確認する。

## 共通の画風（`tools/art/style.md`）

- 16bit 機（SFC）の JRPG フィールド絵、頭身の低いキャラ。
- 全体で **ドットの大きさは1種類**（混在させない＝"mixel" を避ける）。細かさの差は「ドットの大きさ」ではなく「どこに色数と手数を使うか」でつける。
- 色はオブジェクトごとに 12〜16 色程度。明るい側は黄、暗い側は紫・青へ色相をずらす（hue shift）。
- 輪郭は1ドット、隣の色を暗くした「選択的アウトライン」。地面タイルには輪郭をつけない。
- 光源は左上で統一。

## 細かくする所・しない所

| 細かく（色と手数を使う） | 簡素に（大きな面＋影1色・ハイライト1色） |
|---|---|
| 顔（目は2ドット＋ハイライト1、口は1〜2ドット）、手、武器、宝石、看板 | 服・マント・壁・屋根 |
| モンスターの目・口（表情が読める） | 地面（低コントラストの模様で、キャラが浮き立つように） |

小さな絵では「細かさより読みやすさ」。シルエット（1色で塗りつぶしても何か分かるか）と明暗差を優先する。

## 動きのノウハウ（実装時に使う）

- **待機**：2コマを 200〜400ms で往復するのが基本。呼吸は上半身だけ1ドット沈める。まばたきを時々入れる。
- **小さい絵での細かい動き**：位置を1ドット動かすと大きく跳ねて見えるので、輪郭近くの色だけを入れ替える（サブピクセル・アニメーション）か、体は止めて髪・マントなど一部だけ動かす。
- **二次的な動き**：髪・マント・スカートは体より1コマ遅れて追従させる（フォロースルー）。
- **歩き**：接地・通過・接地・通過の4コマが核。通過コマで体を1ドット上げる。
- **攻撃**：振りかぶり（溜め）を長めに見せ、斬撃は短く速く、残像（スミア）を1コマ入れる。被弾は白か赤のフラッシュと2ドットのノックバック。
- **コマ数より一貫性**：コマごとの塊の形がぶれるとガタついて見える。AI 生成のコマはぶれやすいので、参照画像を固定し、小さな動き（呼吸・まばたき・揺れ）はコードで基準コマをずらして作る。

参考：[Lospec: outlines using color](https://lospec.com/articles/pixel-art-outlines-part-2-using-color)、[Pixel Parmesan: anti-aliasing fundamentals](https://pixelparmesan.com/anti-aliasing-fundamentals-for-pixel-artists)、[SLYNYRD Pixelblog 8: Intro to Animation](https://slynyrd.com/blog/2018/8/19/pixelblog-8-intro-to-animation)、[Sub-Pixel Animation](https://someanimatorwannabe.substack.com/p/animator-techniques-sub-pixel-animation)、[Hero idle animation tutorial](https://itch.io/t/2489389/pixel-tutorial-hero-idle-animation)、[How to tame your AI pixel art](https://dev.to/jenissimo/how-to-tame-your-ai-pixel-art-3pk5)

## 絵の約束事（パックを作る人向け）

絵のパックは **PNG と JSON のデータだけ**。コード・プラグイン・任意の処理は含めない。利用者のパックを読み込む画面や見た目選びは、まだ作らない。

- **ID**：`components.json` の既存 ID を役割として保つ。小文字の英数字とハイフンだけ（例 `hero-model`）。PNG は `public/art/<id>.png`、manifest は同じ ID のエントリを1件持つ。
- **コマの名前と並び**：`frames` はギャラリー用の表示名で、PNG の左から右のセル順。コードは名前で参照するので、役割の名前を保つ。歩きの `front pass` など表示名が重複するものだけ、同じ並び・同じ長さの `frameNames` に `front pass L` / `front pass R` のような一意の参照名を足す（絵と表示名は変えない）。そのほかは `frames` が参照名になる。参照名は空・重複を認めない。
- **動きの並び**：`sequences` は今ある動きのコマ名の配列（`idle`、`attack`、`front`、`right`、`back`、`prayer`、`glow`、`fire`、`flap` など）。同じコマを繰り返してよい。`Sheets.pose` は配列から名前を引くだけで、時刻・動きの速さ・描画の処理は今の場面側に残す。仲間の `follow` は現在の追従表示の並び、エフェクトの `slash` / `spell` / `poof`、`claw` / `fire` / `curse` / `rocks` も同様。
- **大きさ**：生成指示の `size` と仕上がりの `frame: [幅, 高さ]` は別。PNG は全コマが同じセルサイズの **横1列**、画像全体の幅＝セル幅×コマ数、高さ＝セル高さ。空きは透明にする。セルサイズは正の整数。背景も実際の仕上がりサイズを記録する。
- **足元**：各エントリの `foot: [x, y]` はセル左上からの、地面に合わせる点（境界も可）。`Sheets.draw` はこの点を指定座標へ合わせ、拡大・左右反転でも同じ点を使う。`pack.py` の既定は `[セル幅/2, セル高さ]`（仕上げ時にそろえた足元）。違う絵は `components.json` に `foot` を指定する。剣先・炎を含む幅の中心で体をそろえ直さない。
- **色の段階**：`hero-model.recolor` に元の `tunic` / `cape`（暗い→明るい）と色違いの `variants` を持つ。色は `#rrggbb`、置き換え先は元と同じ段数。各勇者シートに `recolor` がなければ設定画の段階を使い、設定画にもなければ置き換えない。`bg-battle-*.water` は水の段階 `ramps`、水とみなす最初の段 `minimumSteps`、画像の高さに対する水の開始位置 `horizon`。省略時は従来の水色・境界の推定を保つ。光の塊の自動検出も従来どおり。
- **絵の内部の位置**：`obj-canal.bridge` の `waterFrame` / `deckFrame` はコマ名、`waterRows` は水色を採る行の両端（含む）、`cuts` は橋コマ内の `[左の列, 幅]`。切り出しがセル外へ出ないようにする。橋の上下位置・水路の繰り返し・帯の位置もここにある。外観の `windows` はコマ名ごとの `[足元からの dx, dy, 幅, 高さ]`（窓の中心）で、祈り中の光を絵に合わせる。
- **置き場所**：`bld-inn.town` に5種の部品の選択、建物・小物の足元座標、当たり判定、道の節点と接続を持つ。`inn-wall.inn` にベッドの `slots`・当たり判定・吹き出しと報告の位置、壁・床・じゅうたんの情報、`church-wall.church` に祈る `slots`・神父さま・祭壇・長椅子・燭台・床の情報を持つ。描画・クリック・報告は同じ座標を使う。`town.innSleep.balloon/count` は宿屋の `buildings.inn` の足元から屋根上の Zz・人数までのオフセット。`bg-battle-*.field` は地面の範囲、小物の足元、戦闘の置き場所。洞窟・夜の森の小物の `fieldLight` はコマ名ごとの発光部分の足元相対 `[dx, dy]` で、`field.props` の足元に足して光の中心を求める（光の波形・タイミングは場面側）。横向きモンスターの `reach` は勇者の足元から敵の足元までの間隔。`world-map.regions` は地図の幅・高さに対する地方の町の座標（0〜1）。室内の幅・壁との境・じゅうたんの継ぎ目や、戦闘アップの座標はセルサイズ・足元から求める。

現在の場面が参照する次の役割は必須（動きの配列自体と各コマ名の参照先も検査する）。

| 部品 | 必須の `sequences` 名 |
|---|---|
| `hero-walk` / `hero-walk-back` / `hero-pray` | `front, right` / `back` / `prayer` |
| `party-{warrior,mage,thief,priest}` / 同じ ID の `-back` | `attack, follow` / `attack` |
| `monster-{slime,ghost,golem,dragon}` / 同じ ID の `-side` / `-attack` | `idle` / `idle, attack` / `attack` |
| `ui-weapons` | `tiers`（`iron dagger, blue steel sword, gold legend sword` の順） |
| `church-priest` / `obj-crystal` / `obj-campfire` | `idle` / `glow` / `fire` |
| `fx-battle` / `fx-enemy` | `slash, spell, poof` / `claw, fire, curse, rocks` |
| `amb-butterfly` / `amb-leaf` / `amb-drip` / `amb-gull` | `yellow, white` / `fall` / `splash` / `flap` |

町の `nodes` は、歩行の立ち止まり先・道路描画・門が参照する `plazaW, plazaE, board, shop, well, bridge, fire, crystal, library, homeE, gate` を必ず持つ。ほかの節点は道の接続に応じて変えられるが、すべての `edges` の両端が存在すること。

絵を仕上げ直したら、`python3 tools/art/check_manifest.py` で ID・名前・並び・PNG の大きさ・足元・色・内部位置・参照先・置き場所を確認する（Python 標準ライブラリだけ）。生成元の情報だけ直す時は `uv run --with pillow --with numpy tools/art/pack.py --meta` で manifest へ反映でき、PNG は変わらない。`--meta` は、表示名・分類だけでなく上記の情報と仕上がりの足元も出し、生成元から省略した既知の情報は manifest からも除く。パッキング由来の `frame`・`colors`・`warning` と PNG は保持する。

確認が通っても画風・表情・重なりは機械的には分からないので、`/art.html` と `/mock.html` の全場面（町は5種）を画面写真で確認する。見た目を変えない修正は同じ時刻・乱数・表示サイズでピクセルを比較する。

## コンポーネント一覧

一覧は `/art.html`（ギャラリー）で見る。分類と「使う場面」は `tools/art/components.json` の `group`（大分類）・`sub`（小分類）・`use` に書いてあり、ギャラリーはこの順に並べる。

| 大分類 | 小分類 |
|---|---|
| キャラクター | 勇者（マップ用）／勇者（戦闘フォーカス用）／仲間（マップ用）／仲間（戦闘フォーカス用） |
| モンスター | 横向き（マップ用）／正面（戦闘フォーカス用）／正面の攻撃（戦闘フォーカス用） |
| まち | 建物／広場・小物／宿屋の中／きょうかいの中 |
| フィールド | 地面／自然・水辺／洞窟・夜の森／戦闘背景（戦闘フォーカス用）／背景の動き |
| 演出 | エフェクト／UI |

きょうかいの部品は `church-wall`（ステンドグラスの奥の壁）、`church-altar`（祭壇）、`church-pew`（長椅子）、`church-rug`（青いじゅうたんの奥・中・手前の3コマ）、`church-candles`（燭台）、`church-priest`（神父さまの待機2コマ）。勇者の `hero-pray` は `hero-model` を参照した、画面の奥（上）をまっすぐ向いてひざまずく後ろ姿の2コマで、`fit` で立ち姿の幅に合わせる。壁・じゅうたんも宿屋の対応する部品の幅に合わせる。

勇者の色違い（エージェントごとの服・マントの色）は、パレットの置き換えでコードから作る。
マップ上の横向きモンスターは、真横だと目が片方しか見えず表情が読めないものは斜め向き（3/4）にする（おばけ）。

## 戦闘の見せ方（2通り）

- **マップ上の戦闘**：町とフィールドを1画面で見渡す。勇者は横向き（`hero-battle`）でモンスターと向き合う。エラーや問題が起きるとモンスターが反撃（`monster-*-attack` ＋ `fx-enemy`）し、勇者は被弾する。
- **戦闘にフォーカス**：1人の勇者の戦闘を大きく見せる。パーティーを背中から見る（`hero-back-battle`・`party-*-back`）、背景はフィールドの種類（`bg-battle-*`）、上に「つよさ」、下にメッセージ。
- 組み合わせの見本は `/mock.html`（マップ3種・戦闘4種）。

勇者の色違い（エージェントごとの髪・服・マントの色）は、パレットの置き換えでコードから作る。

## 戦闘背景の動き（`src/web/town/ambient.ts`）

背景は1枚絵のままにし、その上で次のように動かす（モックで使用、本体にもそのまま使う想定）。

- **水の流れ（色の巡回）**：背景のうち、パレットの青・青緑の段階に当たる地平線より下の画素を「水」とみなし、位置と時間で決まる波に合わせて1段明るく・暗くする。16bit 機のカラーサイクリングと同じ考え方で、ドットは動かさず色だけ変える。草原は小川と滝、洞窟は床の水面、夜の森は月を映す池。
- **光**：明るく彩度の高い画素の塊を画像から自動で見つけ、松明・火（暖色）はゆらめき、クリスタル・キノコ（寒色）はゆっくり脈打ち、時々きらめく。夜の森の月は大きく淡く光る。草原は空の青を光と取り違えるので使わない。
- **パーティクル**：草原＝流れる雲（`amb-cloud`）・ちょうちょ（`amb-butterfly`）・綿毛・手前で揺れる草（`amb-grass`）、洞窟＝天井からの水滴と波紋（`amb-drip`）・舞うほこり、夜の森＝ホタル・地面近くの霧・舞い落ちる葉（`amb-leaf`）。

## マップ（箱庭）と表示の切り替え

- マップは独立した箱庭に分ける：**まち**（待機中のエージェントが暮らす。歩き回り、たき火・湖・店・掲示板で立ち止まり、居眠りは宿屋のベッド、呼び出しは手前で手を振る）と、作業中のエージェントが戦う **そうげん**（ファイル編集・任せた仕事のボス戦）・**どうくつ**（テスト・型検査）・**よるのもり**（コマンド実行）。
- 上のタブで切り替える。タブにはそこにいる人数と、見ていないマップで反撃（エラー）や呼び出しが起きた時の印（❗）を出す。
- フィールドで勇者をクリックすると、その勇者の戦闘にフォーカスする（白いフラッシュで切り替え）。戦闘画面をクリックするとフィールドに戻る。
- 勇者はエージェントごとに服とマントの色を変える（パレットの青・赤の段を別の段に置き換え、`Sheets.variant`）。
- 地面は生成タイルを格子に並べると継ぎ目が出るので、タイルの代表色で塗ってから、タイルから切り出した小片を散らして作る（`Sheets.texture`）。

## 大きさをそろえる

- `tools/art/audit.py` で全キャラ・モンスターのコマごとの大きさを測る。
- 生成画像はドットの大きさが毎回違うので、`components.json` の `fit` で「このコマを何ドットにするか」「どのコマと同じ高さ（幅）にするか」を指定し、その大きさになるドット幅で整える。
  勇者は立ち姿 53 ドット、仲間は約 47 ドット。モンスターの攻撃・横向きは、正面の待機と同じ大きさ（ドラゴンは炎を吐いても体の大きさは同じ）。
- コマは足元（下 1/4 の中央）でそろえる。剣を振る・炎を吐くなどで横に伸びても、体の位置はずれない。
- ポーズ同士が横に重なっているシートは、つながった絵の塊ごとにコマへ振り分けて切り出す（剣先などが隣のコマに混ざらない）。

## まちの作り（ドラクエ・FF の町を参考に）

- 広場（噴水）を中心に、宿屋・道具屋の入口を広場へ向ける。教会と図書館は水路の北の一段上の地区、民家は南に柵と庭（井戸・薪・花壇）つき。
- 道は使う人が歩く所だけ、ゆるく曲げて引く。町を歩くエージェントは道に沿って移動する。
- 南に城壁と門。門をクリックすると「どこへ いく？」で各フィールドを選ぶ。フィールドの端の立て札から町や他のフィールドへ移れる。
- 宿屋は外観で見せ、眠っている人数を屋根の上に出す。クリックすると中（同じ大きさのベッドが並ぶ）を見られる。
- きょうかいは「やすむ」（会話の整理）の場所。PreCompact〜PostCompact の間は窓が金色に光り、クリックで中へ。`drawChurch` は宿屋と同じ 960×540 の箱庭・室内の幅で、ステンドグラスの壁、石の床、祭壇、中央のじゅうたん、左右の長椅子と燭台を組み合わせる。祭壇の前で勇者が2コマで祈り、クリックでコマンド窓。「▼ そとへ」で町に戻る。ついていくも追従し、整理が終われば町へ戻る（居眠りは引き続き宿屋）。`/mock.html?scene=church` に同じ描画の見本がある。
- 参考：[RPG Maker: Mapping Towns](https://www.rpgmakerweb.com/blog/mapping-towns)

### 段階5.2：きょうかい・宿屋の室内

- 入口は手前（画面下・利用者側）。`inn-wall` と `church-wall` の生成指示に **no doors, no doorways, no openings** を明記し、奥には窓と連続した壁だけを描く。仕上げた両壁は幅264ドットでそろえ、3枚並べる。
- `church-rug` は1コマ120×30の **奥の端／真ん中／手前の端**。奥の端→真ん中の繰り返し→手前の端を、セルの高さぴったりで画面下の入口から祭壇の下までつなぐ。真ん中には上下の縁・影・房を付けない。生成後の仕上げで中の柄の半周期を上下対称にし、左右の金の帯を全コマで統一、接続する行のRGBAを同一にする（透明な隙間も残さない）。作り直した時も、この接続を確認してから使う。
- `hero-pray` は正面や斜めではなく、顔が見えず赤いマントが見える後ろ姿。生成した基準コマから頭・肩だけ1ドット沈むコマを整え、ひざと足元を固定する。
- 神父さまは祭壇の右に常駐。クリックするたびに4種類の一言を順番にメッセージ欄へ表示し、3番目で「MPが へってきたら ここで いのりなさい。」、4番目で勇者の「やすむ」を案内する。クリックによる回復・整理・コマンド起動などは行わない。位置と一言は `src/web/town/church.ts` を本体とモックで共有する。
- `/art.html` は更新したmanifestから3コマのじゅうたん・背面の祈り・神父さまを一覧表示。`/mock.html?scene=church` でも同じじゅうたん・祈り・神父さまのクリックを確認できる。

### 段階5.3：窓の腰壁・聖職者の装い

- `church-wall` は幅264・高さ約64ドット（仕上がり264×65）。閉じたステンドグラスは壁の上部に置き、下に水平な窓台と連続した石の腰壁・巾木を残す。アーチを床まで延ばさず、扉や出入口は描かない。描画は壁の上端を126に固定し、実際のセルの高さに合わせて床との境を決める。
- `church-priest` は十字飾り付きの背の高いミトラ、足元までの法衣、両肩から垂れる金色のストラを着ける。`fit` は `hero-model` の正面の高さを参照し、帽子込みで53ドット。待機／まばたきの2コマと360msの切り替えは維持する。仕上げでは待機コマを基準に目の閉じる部分だけを変え、帽子・法衣・足元の輪郭を固定する。
- 作り直したら `/art.html` の両部品と `/mock.html?scene=church` を画面写真で確認し、窓台の下に壁が見えることと神父さまの帽子・ストラが読めることを確かめる。

### 段階5.4：祈りの吹き出し

- `ui-prayer-balloon` は、白い吹き出しの中に合わせた両手を描く1コマ。`ui-balloons` を参照し、宿屋の Zz と同じ大きさ・画風にする。既存の `ui-balloons` の絵と0〜6のコマ番号は変更しない。
- `drawChurch` は祈る勇者全員の頭上に描く。宿屋の Zz と同じ500msごとの1ドット上下の揺れで、勇者ごとに400msずらす。本体と `/mock.html?scene=church` は同じ描画を使い、一覧は `/art.html` の「演出／UI」に出す。
- 作り直したら、きょうかいの画面写真で合わせた両手が読めることと、既存の Zz・！などの吹き出しが変わっていないことを確認する。

### 段階7.1：そうびの印と戦闘の演出

- 現在の勇者PNGの剣は、白 `#ffffff`・淡灰 `#c7dcd0`・灰 `#9babb2` を袖・脚・目・紙・斬撃と共有している。剣だけの色の段階は作れないため、服やPNGを変えず **名前札横の武器アイコン** を使う（仕様の代替案）。`ui-weapons` は既存UIを参照して生成・packした3コマ、鉄色／青い鋼／金色。マスタの武器の並び順で選び、3段階以上は金。金だけ時々小さくきらめく。アクセサリのマップ表示はしない。
- 町・宿屋・きょうかい・フィールドでは名前札横、戦闘アップでは先頭のつよさ札の名前横。そうびなしはアイコンを描かず、既存PNG・服の色違い・動きも維持する。
- ダメージ・会心・溜めは `src/core/battle-presentation.ts` の純粋関数。実際の成功だけに数値を出し、未完了・失敗を装備で成功にしない。アクセサリの並び順でためを延ばし、高い段階だけ「ちからを ためている…」。
- モックは `/mock.html?scene=equipment-town`（4勇者の比較）、`/mock.html?scene=equipment-battle`（でんせつ＋高いアクセサリ）。既存場面・タブの見た目は維持する。

## ワールドマップ（プロジェクトが増えた時）

- **でんれい**：全プロジェクト横断で「許可待ち・呼び出し・新しい町・苦戦中・未読の報告」を急ぎの順に並べる。クリックでその町へ。プロジェクトが多くても、普段はこれを上から片付ければよい。
- **動いている町だけを地図に出す**：勇者がいない町は「ねむっている町」の一覧にしまう。
- **地方があふれたらまとめる**：1つの地方の町が 5 つ以上になったら「港町 ×6」の1つの印にまとめ、クリックで一覧から選ぶ。
- **町のすがたは最初に選ぶ**：新しいプロジェクトは、初めて町に入る時に5種類から選ぶ（選んだ地方に町ができる。あとから変えられる）。
- 報告ウィンドウの「ターミナルで ひらく」は、本体ではその勇者の埋め込みターミナルを開く。モックにはターミナルが無いので押せない。
