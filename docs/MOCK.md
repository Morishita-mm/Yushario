# 本番と同じ画面を使うモック

## 入口

- 本番: `/` → `src/web/rpg/main.ts`
- 開発モック: `/mock.html` → `src/web/art/mock.ts`

本番とモックのアプリHTMLを別々には持たない。`src/web/rpg/app.html` をViteが各入口へ挿入する。地図・サイドバー・タブ・勇者の簡易詳細・会話・クエスト・鑑定には、本番の `main.ts` とその部品・CSSをそのまま使う。

## モックだけが持つもの

- `mock-controls.html` / `mock.css`: アプリの**外側**にある折り畳みパネル。場面の移動、勇者の追加、選択した勇者の状態変更。クエスト追加ボタンは、本番の新規クエスト窓を開くだけ。
- `mock-state.ts`: 架空の町・セッション・イベント履歴・クエスト・パーティー。
- `mock-server.ts`: 既存のHTTPとWSの応答。モックページ内だけで `/api/*` のfetchと `/ws`・`/pty` の接続をブラウザ内応答へ置き換える。Viteの通信・絵の読込はそのまま。本番側はこのモジュールをimportしない。
- `mock-quest-api.ts`: クエストに関する既存のHTTP契約のブラウザ内実装。
- `mock-review.ts`, `mock-checks.ts`: 架空の差分と検証結果の値のみ。モック専用の画面は持たない。

本物のCLI・PTY・Git・検証コマンドは実行しない。入力した依頼には「デモの返答」と明示した固定の返答をイベントとして届ける。検証結果は架空の値であり、成功の証拠ではない。端末は本番の窓・描画を使うが、デモの案内を表示するだけで入力を実行しない。

状態はページ内のメモリだけ。再読み込みでデータは戻る。タブや既読など本番と共通の画面設定はブラウザに残る場合がある。自動作戦・本物のworktree操作・外部プレビューなど未対応の操作は409を返し、成功したとは表示しない。

## 本番を直したとき

1. `app.html`、本番のCSS、Scene、Status、会話・クエストなど、通常の本番ファイルを直す。
2. 開発モックでも同じファイルが使われる。サイドバーのスクロールや「同じ勇者を押して詳細を閉じる」処理のコピーはない。
3. HTTP／WSの契約が変わった場合だけ、モックの応答も新しい契約に合わせる。フック・CLIやサーバー側の判断が自動で再現されるわけではない。

本番で追加した部品のHTMLをモックへ転記する必要はない。共通HTMLの変更時は開発サーバーが本番・モックを再読み込みする。

## 手動での確認点

描画・WSのモックだらけのテストは追加せず、coreのテストに加え、実ブラウザで確認する。

- 本番配布物を一時ホームで起動し、表示専用の架空イベントから勇者を20人表示。ページが縦に伸びず、サイドバー内でスクロールすること。
- 本番とモックの両方で、同じ勇者の行を押すと簡易詳細が開き、もう一度押すと閉じ、継続描画後も閉じたままであること。
- モックで勇者を追加してもアプリ全体の高さが変わらないこと。外側パネルを畳むと、その分アプリの使える高さが増えること。
- 外側のクエスト追加から本番の窓が開き、作成・割り当て・依頼・デモの報告・鑑定をたどれること。
- 390px幅では本番と同じ積み上げ配置になり、横にはみ出さないこと。
- `dist/index.html`・`dist/mock.html` に共通HTMLが入っていること。
- モックのアプリAPIやWSが実ネットワークへ送られないこと。

既存の `?scene=town`・`meadow`・`cave`・`forest`・`inn`・`church`・`b-meadow`・`b-cave`・`b-forest`・`b-boss` と装備比較の入口は外側パネルから本番の移動処理へ案内する。配置や勇者は本番のRoom／Sceneから決まり、旧モックの固定位置とは一致しない。
